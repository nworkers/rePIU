# INT 31h AX=0400h trace HLE 설계

## 배경

`INT 2Fh AX=1686h`를 trace 경로에서 처리한 뒤 `piu_1st`는 다음 blocker로 `INT 31h AX=0400h`에 도달했다. 일반 DOS HLE 경로의 `HandleDosHleInstruction`은 이미 `CD 31`을 `HandleDpmiInterrupt31`로 위임하고, 해당 핸들러는 `AX=0400h`에 대해 carry flag를 clear하고 `EIP`를 2바이트 진행하는 최소 응답을 갖고 있다.

문제는 single-step trace 경로가 DOS interrupt pre-handler로 `INT 21h`와 `INT 2Fh`만 먼저 확인한다는 점이다. 따라서 trace 중 관측된 `CD 31`은 일반 HLE 경로에 도달하기 전에 privileged instruction 관측 지점으로 남는다.

## 설계

`INT 31h`는 DPMI 서비스 interrupt이므로 새 의미를 추가하지 않고 기존 `HandleDpmiInterrupt31`을 trace 경로에서도 호출한다.

이번 단계에서는 `AX=0400h`의 기존 최소 응답만 사용한다. 이 호출은 DPMI 기능 질의/상태 확인 계열로 보이며, 현재 목표는 원본 실행 흐름을 다음 관측 지점까지 전진시키는 것이다. 이후 guest가 실제 DPMI state save/restore buffer나 descriptor 조작을 요구하면 해당 호출별로 별도 설계를 추가한다.

## 구현 방침

* trace pre-handler에 `HandleTracedDpmiInterrupt31`을 추가한다.
* `CD 31`을 감지하면 기존 `HandleDpmiInterrupt31`로 위임한다.
* `HandleDpmiInterrupt31`의 `AX=0400h` 처리도 진단 로그에서 마지막 interrupt vector/AX로 보이도록 기록한다.
* `piu_1st` baseline은 새 blocker로 갱신한다.

* `scripts/test_all.ps1`

# INT 31h AX=0400h Trace HLE Design

## Background

After handling `INT 2Fh AX=1686h` in the trace path, `piu_1st` reached the next blocker, `INT 31h AX=0400h`. The general DOS HLE path in `HandleDosHleInstruction` already delegates `CD 31` to `HandleDpmiInterrupt31`, and that handler already has a minimal `AX=0400h` response that clears carry and advances `EIP` by two bytes.

The issue is that the single-step trace path only checks `INT 21h` and `INT 2Fh` in its DOS interrupt pre-handler. As a result, a traced `CD 31` remains as the observed privileged-instruction point before it can reach the general HLE path.

## Design

`INT 31h` is a DPMI service interrupt, so this change does not add new semantics. It calls the existing `HandleDpmiInterrupt31` from the trace path.

For this step, only the existing minimal response for `AX=0400h` is used. This call appears to be in the DPMI query/status family, and the current goal is to advance the original execution flow to the next observation point. If the guest later requires real DPMI state save/restore buffers or descriptor operations, those calls will be designed separately.

## Implementation Policy

* Add `HandleTracedDpmiInterrupt31` to the trace pre-handler.
* Detect `CD 31` and delegate to the existing `HandleDpmiInterrupt31`.
* Record `AX=0400h` handling as the last interrupt vector/AX in diagnostics.
* Update the `piu_1st` baseline to the new blocker.

## Verification

* Build the Win32 x86 host.
* Run `piu_1st` directly and confirm the next observation point.
* Run `scripts/test_all.ps1`.
