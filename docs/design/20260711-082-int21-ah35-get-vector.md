# INT 21h AH=35h 인터럽트 벡터 조회 설계

## 배경

`0x02A0` Port I/O trace-limit를 통과한 뒤 `piu_1st`는 relocated base + `0x000F4955`의 `CD 21`에서 중단되었다. 당시 `EAX=0x00003509`였으므로 요청은 `INT 21h AH=35h AL=09h`, 즉 interrupt 09h vector 조회이다.

원본 코드는 DOS 인터럽트 벡터를 확인한 뒤 자체 처리기 설치 또는 복원 경로를 진행할 가능성이 있다. 현재 HLE는 실제 IVT를 유지하지 않으므로, 우선 실행 전진을 위한 보수적인 최소 응답이 필요하다.

## 설계

`INT 21h AH=35h`를 DOS HLE에 추가한다.

* `AL`의 interrupt 번호는 기록용으로만 사용한다.
* 반환값은 `ES:BX = 0000:0000`으로 둔다.
* carry flag는 clear한다.
* `context->guest_es`와 Win32 `CONTEXT::SegEs`를 함께 `0`으로 갱신한다.
* `BX`는 하위 16비트만 `0`으로 갱신하고 상위 비트는 보존한다.
* 일반 DOS interrupt handler와 traced DOS interrupt handler 양쪽에 같은 의미를 적용한다.

이 응답은 실제 interrupt vector table 모델이 아니라 “아직 이전 DOS 벡터를 제공하지 않는다”는 최소 HLE이다. 이후 원본이 `AH=25h`로 vector 설정을 요청하면 별도 설계로 IVT shadow를 도입할지 판단한다.

## 기대 결과

`piu_1st`는 `INT 21h AH=35h AL=09h` 지점을 지나 다음 실제 HLE 요구사항으로 이동해야 한다.

## 범위 밖

* 전체 interrupt vector table shadow 구현
* `AH=25h` vector 설정 구현
* 실제 keyboard IRQ 처리기 연결

# INT 21h AH=35h Get Vector Design

## Background

After passing the `0x02A0` Port I/O trace limit, `piu_1st` stopped at `CD 21` at relocated base + `0x000F4955`. `EAX=0x00003509`, so the request is `INT 21h AH=35h AL=09h`, get interrupt 09h vector.

The original code likely checks the DOS interrupt vector before installing or restoring its own handler. The current HLE does not maintain a real IVT, so a conservative minimal response is needed to keep execution moving.

## Design

Add `INT 21h AH=35h` to the DOS HLE.

* Use the `AL` interrupt number for observation only.
* Return `ES:BX = 0000:0000`.
* Clear carry flag.
* Update both `context->guest_es` and Win32 `CONTEXT::SegEs` to `0`.
* Update only the low 16 bits of `BX` to `0`, preserving the high bits.
* Apply the same behavior in both the normal DOS interrupt handler and the traced DOS interrupt handler.

This is not a full interrupt vector table model. It is a minimal HLE response that says no previous DOS vector is being provided yet. If the original later requests vector installation with `AH=25h`, a separate design can decide whether to introduce an IVT shadow.

## Expected Result

`piu_1st` should pass the `INT 21h AH=35h AL=09h` point and move to the next real HLE requirement.

## Out Of Scope

* Full interrupt vector table shadow implementation
* `AH=25h` set vector implementation
* Real keyboard IRQ handler wiring
