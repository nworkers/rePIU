# DOS IOCTL HLE 설계

## 배경

`piu_1st`는 `intro.ani` 열기 실패를 처리한 뒤 `0x020F96E1`의 `CD 21`에서 중단된다. 직전 바이트열은 `B0 00 B4 44 CD 21`이며, 실행 로그의 레지스터는 `EAX=0x00004400`, `EBX=0x00000001`이다. 이는 DOS `INT 21h AH=0x44 AL=0x00`, handle `1`에 대한 IOCTL get device information 요청이다.

## 정책

이번 단계에서는 traced DOS HLE 경로에 필요한 최소 IOCTL 의미만 추가한다. 표준 DOS 핸들 `0..4`는 장치 핸들로 취급하고, 열린 파일 핸들은 기존 HLE handle table에 등록된 항목만 파일 핸들로 취급한다.

`AL=0x00` get device information의 반환은 다음과 같이 정한다.

* 표준 핸들 `0..4`: 성공, CF clear, `DX=0x0080`.
* HLE 파일 테이블의 열린 파일 핸들: 성공, CF clear, `DX=0x0000`.
* 알 수 없는 핸들: 실패, CF set, `AX=0x0006`.
* 다른 IOCTL 서브기능은 아직 처리하지 않고 기존처럼 다음 blocker로 남긴다.

`DX=0x0080`은 character device 비트를 나타내며, 현재 관측된 handle `1` stdout 검사에는 충분하다. 장치 속성의 세부 비트와 실제 장치별 동작은 후속 장치 HLE에서 확장한다.

## 검증

`piu_1st` 실행 로그에서 마지막 처리 DOS interrupt가 `AH=0x44`로 갱신되고, 이전 중단점 `0x020F96E1`을 지나 다음 관측 지점으로 이동하는지 확인한다. 전체 회귀는 `scripts\test_all.ps1`로 확인한다.

# DOS IOCTL HLE Design

## Background

After handling the failed `intro.ani` open, `piu_1st` stops at `CD 21` at `0x020F96E1`. The preceding byte sequence is `B0 00 B4 44 CD 21`, and the execution log shows `EAX=0x00004400`, `EBX=0x00000001`. This is a DOS `INT 21h AH=0x44 AL=0x00` IOCTL get device information request for handle `1`.

## Policy

This step adds only the minimum IOCTL semantics needed by the traced DOS HLE path. Standard DOS handles `0..4` are treated as device handles, while opened file handles are recognized only when they exist in the HLE handle table.

`AL=0x00` get device information returns:

* Standard handles `0..4`: success, CF clear, `DX=0x0080`.
* Open HLE file handles: success, CF clear, `DX=0x0000`.
* Unknown handles: failure, CF set, `AX=0x0006`.
* Other IOCTL subfunctions remain unhandled and become the next blocker.

`DX=0x0080` represents the character-device bit and is sufficient for the currently observed stdout handle `1` check. Detailed device attribute bits and real device behavior can be expanded in later device HLE work.

## Verification

Check that the `piu_1st` execution log reports the last handled DOS interrupt as `AH=0x44` and advances past the previous stop at `0x020F96E1` to the next observed point. Run the broader regression with `scripts\test_all.ps1`.
