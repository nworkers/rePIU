# INT 21h AH=0xFF HLE 설계

## 배경

`piu_1st`는 `INT 21h AH=0x30` 처리 후 relocated address `0x020F3954`에서 다시 `CD 21`에 도달한다.
byte window에는 `66 B8 00 FF CD 21`이 포함되므로 이 호출은 `AX=0xFF00`, 즉 `INT 21h AH=0xFF`로 볼 수 있다.

`AH=0xFF`는 일반적인 DOS API 목록의 표준 함수로 보기 어렵다.
현재 관찰에서는 DOS/4G 런타임이 환경 또는 extender 동작을 질의하는 비표준 경로로 취급한다.

## 설계

기존 `enable_dos_version_hle` 플래그를 trace 기반 DOS HLE 플래그로 확장한다.
이 경로는 `piu_1st`에서 실제로 관찰된 `INT 21h` 함수만 처리한다.

초기 지원 함수는 다음과 같다.

* `AH=0x30`: DOS version query
* `AH=0xFF`: DOS/4G 비표준 질의 후보

`AH=0xFF` 처리 규칙은 기존 hello 전용 임시 처리와 동일하게 둔다.

* `AL = 0`
* carry flag clear
* `EIP += 2`

이 값은 아직 의미를 확정한 것이 아니라, 원본 런타임이 다음 코드 경로로 진행하는지 확인하기 위한 최소 HLE 응답이다.

## 검증

* Win32 x86 loader 빌드가 성공해야 한다.
* `piu_1st` 실행에서 handled DOS interrupt count가 2 이상이어야 한다.
* 마지막 DOS interrupt vector는 `0x21`, 마지막 AH는 `0xFF`여야 한다.
* 실행은 `0x020F3954`에서 멈추지 않고 다음 중단 지점으로 진행해야 한다.
* `dos4gw_hello` 출력은 유지되어야 한다.

# INT 21h AH=0xFF HLE Design

## Background

After handling `INT 21h AH=0x30`, `piu_1st` reaches another `CD 21` at relocated address `0x020F3954`.
The byte window contains `66 B8 00 FF CD 21`, so this call is `AX=0xFF00`, or `INT 21h AH=0xFF`.

`AH=0xFF` does not look like a standard DOS API function.
For the current observation, treat it as a DOS/4G non-standard query candidate.

## Design

Extend the existing `enable_dos_version_hle` flag into a trace-based DOS HLE flag.
This path handles only the `INT 21h` functions actually observed on `piu_1st`.

The initial supported functions are:

* `AH=0x30`: DOS version query
* `AH=0xFF`: DOS/4G non-standard query candidate

`AH=0xFF` uses the same behavior as the existing hello-only temporary handling.

* `AL = 0`
* clear carry flag
* `EIP += 2`

This does not finalize the semantic meaning yet; it is the minimal HLE response used to check whether the original runtime can proceed to the next code path.

## Verification

* Win32 x86 loader build must pass.
* `piu_1st` should report handled DOS interrupt count at least 2.
* The last DOS interrupt vector should be `0x21`, and the last AH should be `0xFF`.
* Execution should no longer stop at `0x020F3954`; it should proceed to the next stop.
* `dos4gw_hello` output must be preserved.
