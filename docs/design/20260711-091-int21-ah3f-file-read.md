# INT 21h AH=3Fh 파일 읽기 HLE 설계

현재 `piu_1st`는 `intro.ani`를 `\PIU\INTRO.ANI`로 여는 데 성공한 뒤 `INT 21h AH=3Fh`에서 중단된다. 레지스터 상태는 `AH=3Fh`, `BX=0005h`, `CX=1000h`, `DS:DX`가 guest read buffer를 가리키는 형태이다. 이는 DOS file handle read 요청이다.

`AH=3Fh`는 열린 file handle에서 최대 `CX` 바이트를 읽어 `DS:DX`에 기록하고, 성공 시 carry를 clear하며 `AX`에 실제 읽은 바이트 수를 반환한다. 실패 시 carry를 set하고 `AX`에 DOS error code를 반환한다.

HLE 구현은 기존 `DosVirtualFileSystemState::open_files`를 확장한다. 각 열린 file handle은 host path와 현재 file offset을 가진다. 읽기 요청 시 host file을 binary mode로 열고 offset으로 seek한 뒤 요청 바이트 수만큼 읽는다. 실제 읽은 바이트만 guest buffer에 기록하고, 그만큼 file offset을 증가시킨다. EOF는 성공이며 `AX=0`일 수 있다.

현재 범위에서는 close, seek, sharing, timestamp, device handle read는 구현하지 않는다. Standard handle `0..4`에 대한 read 요청은 아직 관찰되지 않았으므로 invalid handle로 처리한다. 필요하면 별도 작업에서 stdin/device read 정책을 추가한다.

검증은 `piu_1st`가 기존 `AH=3Fh` 지점을 통과하고 다음 관측 지점으로 이동하는지 확인한다. 로그에는 마지막 DOS read handle, requested bytes, actual bytes, result를 출력한다.

# INT 21h AH=3Fh File Read HLE Design

`piu_1st` currently succeeds in opening `intro.ani` as `\PIU\INTRO.ANI`, then stops at `INT 21h AH=3Fh`. The register state has `AH=3Fh`, `BX=0005h`, `CX=1000h`, and `DS:DX` pointing at the guest read buffer. This is a DOS file handle read request.

`AH=3Fh` reads up to `CX` bytes from an open file handle into `DS:DX`. On success it clears carry and returns the actual bytes read in `AX`. On failure it sets carry and returns a DOS error code in `AX`.

The HLE implementation extends the existing `DosVirtualFileSystemState::open_files`. Each open file handle stores the host path and current file offset. On read, the host file is opened in binary mode, seeked to the stored offset, and read for the requested byte count. Only the actual bytes read are written to the guest buffer, and the file offset is advanced by that amount. EOF is successful and may return `AX=0`.

Close, seek, sharing, timestamp, and device handle reads are out of scope for this step. Reads from standard handles `0..4` have not been observed yet, so they are treated as invalid handles. A later task can add stdin/device read policy if needed.

Verification checks that `piu_1st` passes the previous `AH=3Fh` blocker and reaches the next observed point. The log prints the last DOS read handle, requested bytes, actual bytes, and result.
