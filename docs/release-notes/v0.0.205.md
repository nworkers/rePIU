## rePIU v0.0.205

이전 릴리스 **v0.0.204** 이후의 변경입니다(issue #15). **게임 중 `Tab` OSD가 화면 맨 위에 가로로 펼쳐지고, 이름·버전·빌드
날짜와 Target Profile을 먼저 보여 줍니다. OSD와 런처의 글자는 창을 키우면 함께 커집니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#15](https://github.com/reexec/rePIU/issues/15) | re2DJ 형태의 OSD, OSD와 런처 글자가 창 크기에 비례 | `d44a1e5` |

### 새로 들어온 것

**OSD 배치 (#15).** [re2DJ](https://github.com/nworkers/re2DJ)의 OSD와 같은 형태입니다.

* 화면 맨 위에 가로 전체 폭으로 붙고, 높이는 내용만큼입니다.
* 첫 줄: `rePIU v0.0.205 (Win/x86 Release) - Build …`(창 제목과 같은 표기). 둘째 줄: `Target Profile : pumpit1`처럼 지금
  실행 중인 롬셋. 그 아래로 v0.0.204의 Renderer 절, LFB 토글, 화면 shader 메뉴가 이어집니다.

**창 크기에 비례하는 글자 (#15).**

* OSD의 글자와 여백이 창 높이에 맞춰 커집니다. 1배 창(640×480)에서 0.75배, 기본 2배 창에서 1.5배, 4K 전체화면에서 3.375배입니다.
  전에는 창을 키워도 글자가 13 px 그대로라 상대적으로 작아졌습니다.
* **인자 없이 실행했을 때의 런처**도 이제 창 크기를 바꾸거나 최대화할 수 있고, 글자·표·버튼이 함께 커집니다. 기본 크기에서는
  이전과 같습니다. 런처에 항상 보이던 세로 스크롤바도 없어졌습니다.

**폰트.** OSD와 런처 모두 re2DJ와 같은 ProggyForever(Dear ImGui의 확대에 강한 기본 폰트)로 그립니다. 이를 위해 Dear ImGui를
v1.92.1에서 v1.92.9로 올렸습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드, `repiu_core_probe`·`repiu_aot_probe --imgui-ui-scale`, pumpit1 OSD 캡처(1배·2배·4K 전체화면), 런처 캡처(기본 960×640·최대화 3840×2054) |
| Linux x64 Debug (WSL) | 빌드, `repiu_core_probe` 전체 통과 |
| Win32 x86 Debug (CI) | 빌드와 probe |

### 알려진 것

* 새 OSD 배치는 Linux에서 화면으로 확인하지 못했습니다(같은 공용 코드이고, v0.0.204의 OSD는 Linux에서 화면으로 확인했습니다).
* 런처 기본 크기에서 긴 제목이 Status 열 경계까지 닿습니다(이전과 같음). 창을 키우면 풀립니다.
* 이전 릴리스의 "알려진 것"은 그대로입니다: [#7](https://github.com/reexec/rePIU/issues/7) i386 Wayland(NVIDIA) 창 생성 실패,
  [#8](https://github.com/reexec/rePIU/issues/8) Win32 Release core probe의 `stack_bridge_contract`,
  [#12](https://github.com/reexec/rePIU/issues/12) 릴리스 CI의 Linux x64 `host_thread_interrupt` 간헐 실패.

## rePIU v0.0.205

Changes since the previous release, **v0.0.204** (issue #15). **The in-game `Tab` OSD now spans the top of the screen and
opens with the name, version, build date and Target Profile, and OSD and launcher text grows with the window.**

### Resolved issues

| Issue | Summary | Commit |
|---|---|---|
| [#15](https://github.com/reexec/rePIU/issues/15) | The OSD in re2DJ's layout; OSD and launcher text that scales with the window | `d44a1e5` |

### New

**OSD layout (#15).** The same layout as [re2DJ](https://github.com/nworkers/re2DJ)'s OSD.

* Across the full width at the top of the screen, as tall as its content.
* First line: `rePIU v0.0.205 (Win/x86 Release) - Build …` (written as in the window title). Second line: the running ROM
  set, as in `Target Profile : pumpit1`. v0.0.204's Renderer section, the LFB toggle and the screen shader menu follow.

**Text that scales with the window (#15).**

* OSD text and spacing grow with the window height: 0.75x in a 1x window (640×480), 1.5x in the default 2x window, 3.375x in
  4K fullscreen. Before, the text stayed at 13 px however large the window, and so looked ever smaller.
* **The launcher shown without arguments** can now be resized and maximised, and its text, table and buttons grow with it.
  The default size looks as before, and the vertical scroll bar it always showed is gone.

**Font.** The OSD and the launcher both draw with ProggyForever, Dear ImGui's scalable default font, as re2DJ does. Dear ImGui
moves from v1.92.1 to v1.92.9 for it.

### Verified

| Configuration | Check |
|---|---|
| Win32 x86 Release | build, `repiu_core_probe` and `repiu_aot_probe --imgui-ui-scale`, pumpit1 OSD captures (1x, 2x, 4K fullscreen), launcher captures (default 960×640, maximised 3840×2054) |
| Linux x64 Debug (WSL) | build; the whole `repiu_core_probe` passes |
| Win32 x86 Debug (CI) | build and probes |

### Known

* The new OSD layout was not checked on screen on Linux (it is the same shared code, and v0.0.204's OSD was checked on
  screen on Linux).
* At the launcher's default size, long titles reach the Status column's edge (as before); enlarging the window clears it.
* Earlier known issues remain: [#7](https://github.com/reexec/rePIU/issues/7) i386 on Wayland (NVIDIA) failing to create
  its window, [#8](https://github.com/reexec/rePIU/issues/8) the Win32 Release core probe's `stack_bridge_contract`, and
  [#12](https://github.com/reexec/rePIU/issues/12) the intermittent Linux x64 `host_thread_interrupt` failure in the release
  CI.
