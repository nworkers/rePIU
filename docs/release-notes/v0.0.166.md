## rePIU v0.0.166

이전 릴리스 **v0.0.165** 이후의 변경입니다. **실행이 자기 프레임률을 보고합니다.**

### 실행마다 나오는 줄이 달라졌습니다

종료 줄에 `frames=`와 `span_ms=`가 붙습니다. 이 줄을 파싱하는 도구가 있으면 형식 변경을
확인하십시오.

```
[repiu-shutdown] reason=timeout … gate=0 frames=2440 span_ms=87901
```

* `span_ms`는 **첫 프레임부터** 종료까지입니다. 예산 전체가 아닙니다.
* `REPIU_GLIDE_FRAME_RATE_LOG=1`이면 초당 한 줄이 추가로 나옵니다. 창 제목에 쓰던 것과 같은
  값입니다.

절차는 [실행 프레임률 측정 절차](../guides/execution-frame-rate-measurement.md)에 있습니다.

### 측정 — Linux는 Windows의 3.7%입니다

같은 기계, `pumpit1`, 90초, vsync OFF, 양쪽 Release, 호스트당 3회입니다.

| 호스트 | 평균 fps | 프레임당 |
|---|---:|---:|
| Windows | 730.05 | 1.37 ms |
| Linux (WSLg) | 27.21 | 36.75 ms |

약 26.8배이고 두 집단의 범위가 겹치지 않습니다. **기동은 원인이 아닙니다** — 양쪽 다 첫
프레임까지 2초 남짓입니다.

### 알려진 것

- **probe 모음이 Release에서 검증된 적이 없습니다.** Linux Release는 segfault, Windows
  Release는 2건 실패, Debug는 양쪽 15/15입니다. 엔진 자체는 Release에서 정상입니다.
- 26.8배 안에 컴파일러 차이와 WSLg의 X11 한 겹이 아직 함께 들어 있습니다.

## rePIU v0.0.166

Changes since **v0.0.165**. **A run now reports its own frame rate.**

### The line every run prints has changed

`frames=` and `span_ms=` are appended to the shutdown line. If anything parses that line, check the
format change.

```
[repiu-shutdown] reason=timeout … gate=0 frames=2440 span_ms=87901
```

* `span_ms` runs **from the first frame** to shutdown, not over the whole budget.
* `REPIU_GLIDE_FRAME_RATE_LOG=1` adds one line a second -- the same value the window title carries.

The procedure is in [Measuring the execution frame rate](../guides/execution-frame-rate-measurement.md).

### Measured — Linux runs at 3.7% of Windows

Same machine, `pumpit1`, 90 seconds, vsync off, Release on both, three runs per host.

| Host | Mean fps | Per frame |
|---|---:|---:|
| Windows | 730.05 | 1.37 ms |
| Linux (WSLg) | 27.21 | 36.75 ms |

About 26.8x, with the two groups not overlapping. **Start-up is not the cause** -- both reach their
first frame in about two seconds.

### Known

- **The probe suite has never been validated in Release.** Linux Release segfaults, Windows Release
  fails two, and Debug passes 15 of 15 on both. The engine itself is fine in Release.
- The 26.8x still contains both the compiler difference and WSLg's extra layer of X11.
