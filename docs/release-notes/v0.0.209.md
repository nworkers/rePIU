## rePIU v0.0.209

이전 릴리스 **v0.0.208** 이후의 변경입니다(issue #24). **진단처럼 보이는 이름 뒤에 숨어
있던 끄기 스위치 3개와, 기본으로 꺼져 있던 DOS/DPMI 실험 2개를 지웠습니다.** 아무 변수도
주지 않은 실행의 동작은 v0.0.208과 같습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#24](https://github.com/reexec/rePIU/issues/24) | 진단 이름 뒤에 숨은 끄기 스위치와 DOS/DPMI 실험 두 개 삭제(환경 변수 토글 정리 3번 묶음) | `5444d28` |

### 바뀐 것

**더 이상 읽지 않는 환경 변수 6개.** 설정해도 아무 효과가 없습니다.

* 기능은 항상 켜져 있고 끄는 길만 없어진 것: `REPIU_GLIDE_DRAW_ENTRY_POINTS`(point·AA·
  polygon 진입점 그리기), `REPIU_TIMER_TICK_BACKLOG`(밀린 timer tick 보존),
  `REPIU_JAMMA_SNAPSHOT`(입력 스냅샷). 스냅샷 주기 `REPIU_JAMMA_SNAPSHOT_US`는 그대로
  동작하며 `0`이면 매 읽기 조회가 됩니다.
* 기능째 없어진 실험: `REPIU_DOS4GW_MEMORY_PATH_PROBE`(DOS 버전 응답에 PharLap 표지를 붙이던
  실험), `REPIU_DPMI_1E7F_PROBE_SUCCESS`·`REPIU_DPMI_1E7F_TRACE`(`INT 31h AX=1E7Fh`에 가짜
  성공을 돌려주던 진단 — 이 호출은 이미 고친 스택 손상에서 나온 것이었습니다).

**진단 출력 형식이 바뀌었습니다.** 지운 값은 기본 실행에서 항상 0이었습니다.

* 종료 로그의 tick 줄이 `timer tick delivery due/injected/dropped/deferred/max-backlog/remaining`
  으로 바뀌고(`backlog-enabled`·`coalesced` 열 삭제), 게이트 줄은 `timer tick in-gate due: N`
  이 됩니다.
* CD 오디오 위치 census 파일에서 `ticks_coalesced`·`ticks_coalesced_in_gate` 열이 빠집니다.
  — 이 형식을 읽는 자체 스크립트가 있다면 함께 고쳐야 합니다.

**probe.** v0.0.208에서 실행 시간 버킷 하나를 지운 뒤 맞지 않던 `repiu_aot_probe`의 기대값을
고쳐, Win32에서 probe 체인이 끝까지 돕니다.

**스크립트·문서.** backlog 스위치 A/B 스크립트 `task366`을 지우고 `task414`는 새 로그 줄에
맞췄습니다. frontier 문서의 토글 표를 현재 상태로 고쳤고, README의 텍스처 덤프 항목을 실제
변수 `REPIU_GLIDE_TEX_DUMP`로 바로잡았습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 Release | 빌드, `repiu_aot_probe` 전체 체인(종료 코드 0), timer tick probe, Glide probe 2종, pumpit2a 60초를 v0.0.207 릴리스와 두 쌍 교대 실행(fault 0, 둘째 쌍 프레임 3,202 / 3,203) |
| Linux x64 Release | 빌드, core probe 39개 통과 |

### 알려진 것

* Linux i386 빌드는 확인하지 않았습니다.
* Win32 core probe의 `stack_bridge` 실패는 이전부터 있던 것입니다(#8).
* 첫 번째 pumpit2a 쌍에서는 새 빌드가 순간 끊김 두 번으로 약 1초 뒤처졌지만, 둘째 쌍에서
  초당 fps까지 일치해 실행 편차로 판정했습니다.

## rePIU v0.0.209

Changes since **v0.0.208** (issue #24). **Three kill switches hidden behind diagnostic names
and two default-off DOS/DPMI experiments are gone.** A run with nothing set behaves as
v0.0.208 did.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#24](https://github.com/reexec/rePIU/issues/24) | Retire the kill switches hidden behind diagnostic names and two DOS/DPMI experiments (environment toggle cleanup, group 3) | `5444d28` |

### Changed

**Six variables are no longer read**; setting them has no effect. The features stay always on
and only the off switch is gone for `REPIU_GLIDE_DRAW_ENTRY_POINTS` (drawing the point, AA and
polygon entry points), `REPIU_TIMER_TICK_BACKLOG` (keeping owed timer ticks) and
`REPIU_JAMMA_SNAPSHOT` (the input snapshot); the snapshot interval `REPIU_JAMMA_SNAPSHOT_US`
still works, and `0` queries on every read. The experiments themselves are gone for
`REPIU_DOS4GW_MEMORY_PATH_PROBE` (a PharLap marker on the DOS version reply) and
`REPIU_DPMI_1E7F_PROBE_SUCCESS`/`REPIU_DPMI_1E7F_TRACE` (a fake success for `INT 31h AX=1E7Fh`, a
call that came from stack corruption fixed long ago).

**Diagnostic output changed format**; every removed value was always zero in a default run.
The final log's tick line becomes
`timer tick delivery due/injected/dropped/deferred/max-backlog/remaining` (the `backlog-enabled`
and `coalesced` columns go) and the gate line becomes `timer tick in-gate due: N`; the CD audio
position census file loses its `ticks_coalesced` and `ticks_coalesced_in_gate` columns — update
any script of your own that reads these formats.

**Probe**: the `repiu_aot_probe` expectation left stale by v0.0.208's removal of an execution
time bucket is fixed, so the probe chain runs to the end on Win32.

**Scripts and docs**: the backlog A/B script `task366` is deleted and `task414` follows the new
log line; the frontier's toggle table shows the current state, and README's texture dump entry
names the real variable, `REPIU_GLIDE_TEX_DUMP`.

### Verified

* Win32 Release: build; the full `repiu_aot_probe` chain (exit 0); the timer tick probe; both
  Glide probes; two alternating 60 s pumpit2a pairs against the v0.0.207 release (zero faults,
  3,202 / 3,203 frames in the second pair).
* Linux x64 Release: build; all 39 core probes pass.

### Known

* The Linux i386 build was not checked.
* The Win32 core probe's `stack_bridge` failure predates this release (#8).
* In the first pumpit2a pair the new build fell about a second behind after two hitches; the
  second pair matched down to the per-second fps, so it was judged run-to-run variation.
