## rePIU v0.0.151

이전 릴리스 **v0.0.150** 이후의 변경입니다. 이번 릴리스는 `pumpit8` 실행 로그에 남아 있던
Glide 구현 공백 두 개를 없애 LFB region 전송을 구현하고, 그 결과 드러난 다음 종료 원인인
DOS 파일 생성·쓰기 서비스를 추가합니다.

### Glide LFB region 전송

- `grLfbReadRegion@28`(ordinal 98)은 픽셀을 복사하지 않고 성공만 돌려주는 no-op이었고,
  `grLfbWriteRegion@32`(ordinal 99)는 source format을 거부했습니다. `pumpit8`은 두 함수를
  각각 **1,440회**(`3 x 480`) 호출합니다. 전면 화면을 한 행씩 읽어 가공한 뒤 되쓰는
  합성을 3회 수행하는 것이며, 양쪽 모두 실행되지 않고 있었습니다.
- `kGlideLfbSrcFmt565`가 `1`로 정의되어 있었습니다. Glide 2.4에서 `1`은 555이고 565는 `0`
  이므로, 게임이 쓰는 8888뿐 아니라 진짜 565 요청도 거부되고 있었습니다. `GrLfbSrcFmt_t`
  전체를 사양값으로 정정했습니다.
- `stride = 0`이 "빈 영역"으로 해석되고 있었습니다. 한 행 전송에서 stride는 쓰이지 않는
  자리이므로 `width * bytes-per-pixel`로 유도합니다.
- 기존 write 경로는 region을 staging surface에 쓴 뒤 **surface 전체**를 present하는데, 그
  surface는 프레임 버퍼로 seed되지 않았습니다. 포맷만 고쳤다면 한 행만 새 값인 640x480
  이미지를 프레임당 480회 덮어써 화면이 파괴되었을 것입니다.
- 두 gate가 staging surface를 프레임 버퍼 shadow로 공유합니다. ensure/flush/invalidate 세
  연산으로 region이 아닌 gate 진입 전에 한 번만 present하므로, 연속 호출 한 묶음이
  readback 1회 + present 1회로 끝납니다. 행마다 처리하면 프레임당 전체 화면 왕복이 행
  수만큼 발생합니다.
- 포맷 표, stride 규칙, 사각형 클립, 픽셀 변환을 `glide_lfb_region` 모듈로 분리했습니다.
  boundary에는 ABI 해석, guest 범위 검사, shadow 수명만 남습니다. 565/555/1555/888/8888을
  지원하고 깊이 계열, `RLE16`, 음수 stride, lock 중 요청은 거절하고 기록합니다.

### LFB region 좌표계와 색 순서 정정

첫 구현은 화면을 상하 반전시키고 red와 blue를 교환했습니다. 실행 결과로 가정 두 개가
반증되었습니다.

- **region 좌표는 origin 상대가 아닙니다.** `grLfbLock`은 `GrOriginLocation_t`를 명시적으로
  받지만 region 전송 두 개는 받지 않습니다. 인자를 생략한 것이 아니라 프레임 버퍼를 native
  배치(행 0 = 화면 위)로 주소지정하기 때문입니다. `pumpit8`의 창은
  `GR_ORIGIN_LOWER_LEFT`이며, lock처럼 행을 뒤집으면 전면 화면이 반전됩니다.
- **source word의 채널 순서는 `grLfbWriteColorFormat`을 따릅니다.** `GrLfbSrcFmt_t`는 픽셀의
  크기와 비트 폭만 정합니다. `pumpit8`은 `cFormat = ABGR`, `grLfbWriteColorFormat(ABGR)`
  이므로 8888 word의 메모리 배치는 `R,G,B,A`이고, 이를 ARGB로 읽으면 red와 blue가
  교환됩니다. 변환은 source 색 형식으로 풀어 목적지 색 형식으로 싸며, 두 형식이 같으면
  무변환 통과입니다.
- 이는 design 360의 "`GR_LFB_SRC_FMT_565` source는 명시적 RGB565"라는 추정을 반증합니다.
  그 추정은 당시 검증이 불가능했습니다 — `grLfbWriteRegion`은 이번 작업 전까지 한 번도
  성공한 적이 없습니다. lock write mode에 대한 design 360의 결론은 그대로 유효합니다.
- 함께 정정한 관측 오류가 하나 있습니다. 구현 공백 기록에 남은 서로 다른 인자 조합이 정확히
  128개라 "하단 128행"으로 정리했으나, 128은 `kGlideImplementationIssueRecordCapacity`이지
  행 수가 아닙니다. **구현 공백 기록 건수를 호출 횟수로 읽으면 안 되며**, 호출 횟수는 Glide
  call trace의 `count`에 있습니다.

### DOS 파일 생성·쓰기 서비스

- LFB 수정 뒤 `pumpit8`은 약 25초를 구동한 뒤 `unsupported DOS INT 21h AH=0x3c`로
  종료했습니다. `0x040F8417`의 바이트는 `mov ah,3Ch` / `int 21h`이고 `DS:EDX`는
  `"ERRLOG.txt"`, `CX = 1`(read-only)입니다. 게임이 자기 오류 로그를 만들려는 것입니다.
- DOS 가상 파일 시스템은 읽기 전용이었습니다. 열기·읽기·탐색·닫기만 있고, `AH=40h`는
  handle을 보지 않고 전량 콘솔로 보낸 뒤 성공을 보고했습니다. 게스트가 파일에 쓴 내용은
  어디에도 남지 않았습니다.
- `CreateDosFile`과 `WriteDosFile`을 추가했습니다. 생성 파일은 mount root 아래 게스트 경로
  그대로 만들어 기존 읽기 경로가 그대로 찾습니다. handle은 기존 lowest-free 규칙(Task 228)
  을 쓰고, 읽기 캐시(Task 374)와 같은 규약의 출력 스트림 캐시를 갖습니다. 쓰기는
  `cached_file_size`를 갱신하고 같은 handle의 읽기 캐시를 무효화합니다.
- 생성 속성은 호스트 파일에 적용하지 않고 `attribute_overrides`에 기록합니다. 게임은
  read-only로 만든 뒤 그 handle로 계속 쓰는데, DOS에서는 정상이지만 호스트에
  `FILE_ATTRIBUTE_READONLY`를 걸면 바로 다음 쓰기가 막힙니다.
- `AH=40h`는 VFS의 열린 쓰기 가능 handle이면 파일로, 그 외(표준 handle 0~4 포함)에는 기존
  콘솔 경로 그대로 갑니다. VFS handle은 5부터 할당되므로 표준 출력은 영향이 없습니다.
- 쓰기를 `dos_file_io` trace에 남기고, trace prefix가 16바이트뿐이라 `[repiu-dos] write`
  줄로 본문을 최대 240바이트씩 64회까지 함께 기록합니다. 게임 자신의 오류 보고가 우리
  로그에서 읽힙니다.

### 검증

- Win32 x86 Debug 전체 빌드가 성공했습니다.
- `glide_lfb_region_probe` 7개 항목(포맷 표, stride 규칙, 픽셀 변환, 색 순서, 클립, 왕복,
  행 대응)이 모두 통과했습니다.
- `dos_file_create_probe` 8개 항목(생성과 handle 번호, 절단, 부모 디렉터리 없음, 쓰기
  오프셋과 캐시 크기, 생성·쓰기·닫기·재개봉 왕복, read-only 속성, handle 20칸 소진)이 모두
  통과했습니다. probe는 임시 디렉터리를 자기 루트로 쓰므로 실패해도 runtime mount에 아무것도
  남기지 않습니다.
- `repiu_aot_probe`가 exit 0으로 끝나 기존 probe 회귀가 없음을 확인했습니다.
- LFB 수정 후 구동에서 Glide 구현 공백(`repiu-fatal`)이 **0건**이고, Glide direct dispatch
  성공 295,301회, MP3 194프레임 디코드를 기록했습니다.

### 알려진 제한

- 정정본의 실물 구동 화면 확인은 하지 않았습니다. probe와 빌드까지만 검증했습니다.
- 게임이 `ERRLOG.txt`에 무엇을 쓰는지, 그 파일을 항상 만드는지 오류를 감지했을 때만 만드는지
  아직 모릅니다. 다음 구동 로그의 `[repiu-dos] write` 줄로 판별됩니다.
- region 합성이 read 결과를 어떻게 쓰는지(알파 합성인지 단순 덮어쓰기인지) 관측하지
  않았습니다.
- 생성 파일은 mount root 아래에 있으므로 mount cache가 무효화되면 재추출과 함께 지워집니다.
  로그성 파일에는 맞는 성질이며, 영속성이 필요한 게스트 쓰기가 관측되면 그때 overlay를
  설계합니다.
- `AH=5Bh`(create new), `41h`(delete), `56h`(rename), `39h`/`3Ah`(mkdir/rmdir)는 관측되지
  않아 구현하지 않았습니다.
- 깊이 계열 source format, `RLE16`, 음수 stride, `AUX`/`DEPTH` 버퍼 region 전송은 구현하지
  않았습니다.
- burst 사이에 region이 아닌 gate가 끼면 그만큼 readback과 present가 늘어납니다. 실제 호출
  순서는 아직 관측하지 않았으며 `glide_lfb_region_seed_count`와
  `glide_lfb_region_flush_count`로 확인할 수 있습니다.

## rePIU v0.0.151

Everything since the previous release, **v0.0.150**. This release closes the two Glide
implementation gaps left in the `pumpit8` run log by implementing the LFB region transfers, and adds
the DOS file create and write services that the next termination revealed.

### Glide LFB region transfers

- `grLfbReadRegion@28` (ordinal 98) returned success without copying pixels, and
  `grLfbWriteRegion@32` (ordinal 99) rejected its source format. `pumpit8` calls each **1,440
  times** (`3 x 480`) — three full-screen composites that read one row, transform it, and write it
  back — and neither half was running.
- `kGlideLfbSrcFmt565` was defined as `1`, but Glide 2.4 puts 555 at `1` and 565 at `0`, so the
  test rejected the 8888 the game passes and genuine 565 as well. The whole `GrLfbSrcFmt_t` set is
  corrected to its specification values.
- A `stride` of `0` read as an empty region. A single-row transfer never consults a stride, so it is
  derived as `width * bytes-per-pixel`.
- The old write path wrote the region into the staging surface and then presented the *entire*
  surface, which was never seeded from the frame buffer. Fixing only the format would have blitted a
  640x480 image with one fresh row over the screen 480 times per frame.
- Both gates now share the staging surface as a frame buffer shadow with ensure, flush, and
  invalidate, presenting once before the next non-region gate, so a burst costs one readback and one
  present instead of one of each per row.
- The format table, stride rule, rectangle clipping, and pixel conversion moved into a
  `glide_lfb_region` module, leaving ABI decoding, guest-range checks, and shadow lifetime in the
  boundary. 565/555/1555/888/8888 are supported; depth formats, `RLE16`, negative strides, and
  requests made under an outstanding lock are declined and recorded.

### LFB region orientation and color-order correction

The first implementation rendered the screen upside down with red and blue swapped, refuting two
assumptions.

- **Region coordinates are not origin-relative.** `grLfbLock` takes an explicit
  `GrOriginLocation_t` and the region entry points take none — not an omission, but because they
  address the frame buffer in its native layout with row 0 at the top. `pumpit8`'s window is
  `GR_ORIGIN_LOWER_LEFT`, where mirroring rows the way a lock would inverts the full screen.
- **The source word's channel order follows `grLfbWriteColorFormat`.** `GrLfbSrcFmt_t` fixes only
  the pixel's size and bit widths. `pumpit8` uses `cFormat = ABGR` and calls
  `grLfbWriteColorFormat(ABGR)`, so an 8888 word is `R,G,B,A` in memory and reading it as ARGB swaps
  red and blue. Conversion unpacks in the source format and packs in the destination format, passing
  through unchanged when the two agree.
- This refutes design 360's inference that a `GR_LFB_SRC_FMT_565` source is explicitly RGB-ordered.
  That inference could not have been tested then, because `grLfbWriteRegion` never once succeeded
  before this work; design 360's conclusions about lock write modes still stand.
- One observation error is corrected alongside: distinct argument sets in the implementation-gap
  record stopped at exactly 128, which was read as "the bottom 128 rows". 128 is
  `kGlideImplementationIssueRecordCapacity`, not a row count. **Issue record counts are not call
  counts** — the Glide call trace `count` is.

### DOS file create and write services

- With the LFB path fixed, `pumpit8` ran about 25 seconds and stopped with
  `unsupported DOS INT 21h AH=0x3c`. The bytes at `0x040F8417` are `mov ah,3Ch` / `int 21h` with
  `DS:EDX` at `"ERRLOG.txt"` and `CX = 1` (read-only): the game creating its own error log.
- The DOS virtual file system was read-only — open, read, seek, close — and `AH=40h` ignored the
  handle, sent everything to the console, and reported success, so nothing a guest wrote was kept.
- `CreateDosFile` and `WriteDosFile` add the missing half. Created files land under the mount root at
  the guest's own path, so the unchanged read path finds them again; handles use the existing
  lowest-free rule (Task 228) and carry an output stream cache matching the read cache's contract
  (Task 374), with writes updating `cached_file_size` and invalidating the read cache on the same
  handle.
- The creation attribute is recorded in `attribute_overrides` rather than applied to the host file:
  the guest creates read-only and then writes through that same handle, which DOS allows and a host
  `FILE_ATTRIBUTE_READONLY` would block.
- `AH=40h` routes an open writable VFS handle to its file and leaves every other handle, standard
  handles 0-4 included, on the console path. VFS handles start at 5, so standard output is
  unaffected.
- Writes are traced in `dos_file_io`, and because the trace prefix holds only 16 bytes, up to 64
  writes are also recorded as `[repiu-dos] write` lines carrying up to 240 bytes of text, making the
  game's own error report readable from our log.

### Verification

- The full Win32 x86 Debug build passed.
- All seven `glide_lfb_region_probe` checks passed: format table, stride rule, pixel conversion,
  color order, clipping, round trip, and row mapping.
- All eight `dos_file_create_probe` checks passed: creation and handle numbering, truncation, a
  missing parent directory, write offsets and cached size, a create/write/close/reopen round trip,
  the read-only attribute, and handle exhaustion at 20 slots. The probe roots itself in a temporary
  directory, so a failed run leaves nothing in a runtime mount.
- `repiu_aot_probe` exits 0, confirming no existing probe regressed.
- The post-fix run recorded **zero** Glide implementation gaps, 295,301 successful Glide direct
  dispatches, and 194 decoded MP3 frames.

### Known limitations

- The corrected build was not confirmed on screen; verification stopped at the probes and the build.
- What the game writes into `ERRLOG.txt`, and whether it creates that file unconditionally or only
  on detecting a fault, is unknown. The next run's `[repiu-dos] write` lines answer it.
- How the region composite consumes its read result — alpha composite or plain overwrite — has not
  been observed.
- Created files live under the mount root and disappear when the mount cache is invalidated and
  re-extracted. That suits a log file; the first durable guest write we observe is when an overlay
  becomes worth designing.
- Create-new (`5Bh`), delete (`41h`), rename (`56h`), and mkdir/rmdir (`39h`/`3Ah`) are not
  implemented, none having been observed.
- Depth-carrying source formats, `RLE16`, negative strides, and `AUX`/`DEPTH` buffer region
  transfers are not implemented.
- A non-region gate interleaved into a burst adds a readback and a present. The actual call order
  has not been observed; `glide_lfb_region_seed_count` and `glide_lfb_region_flush_count` report it.
