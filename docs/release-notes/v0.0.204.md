## rePIU v0.0.204

이전 릴리스 **v0.0.203** 이후의 변경입니다(issue #5). **게임 중 `Tab` OSD 맨 위에 지금 화면을 그리는 OpenGL
renderer가 나오고, 소프트웨어 렌더러면 경고합니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#5](https://github.com/nworkers/rePIU/issues/5) | 인게임 OSD에 OpenGL renderer 표시 | `7edcfa2` |

### 새로 들어온 것

**OSD의 Renderer 절 (#5).** `Tab`으로 여는 OSD 맨 위에 다음이 나옵니다.

* renderer(예: `NVIDIA GeForce RTX 4090/PCIe/SSE2`), vendor, OpenGL 버전.
* SDL 비디오 드라이버: Windows는 `windows`, Linux는 `x11` 또는 `wayland`. WSL에서 엔진이 Mesa D3D12를 골랐으면 그렇게
  덧붙입니다.
* llvmpipe, softpipe, swrast, GDI Generic(Windows에서 GPU 드라이버가 없을 때), WARP, SwiftShader 같은 **소프트웨어
  렌더러면 빨간 글씨와 "Software rendering: no 3D acceleration"**. 게임이 유난히 느리면 먼저 여기를 보십시오.

표시만 하며 GL 호출을 더하지 않습니다. 로그에는 기존 `GL renderer:` 줄 옆에
`GL vendor/version/video driver/software: …` 한 줄이 더해졌습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드, `repiu_core_probe`·`repiu_aot_probe --gl-renderer-identity`, pumpit1에서 OSD 캡처(RTX 4090, `windows`) |
| Linux x64 Debug (WSL) | 빌드, `repiu_core_probe` 전체 통과, `GALLIUM_DRIVER=llvmpipe`로 pumpit1을 실행해 경고 캡처(`x11`) |
| Win32 x86 Debug (CI) | 빌드와 probe |

### 알려진 것

* 소프트웨어 판정은 이름 목록입니다. 목록에 없는 소프트웨어 렌더러는 경고 없이 이름만 보입니다.
* Linux i386과 Wayland에서는 이번 기능을 실행해 보지 않았습니다(같은 코드입니다).
* v0.0.203의 "알려진 것"은 그대로입니다: i386 Wayland(NVIDIA) 창 생성 실패([#7](https://github.com/nworkers/rePIU/issues/7)),
  Win32 Release core probe의 `stack_bridge_contract`([#8](https://github.com/nworkers/rePIU/issues/8)). 릴리스 CI의 Linux x64
  `host_thread_interrupt` 간헐 실패([#12](https://github.com/nworkers/rePIU/issues/12))도 추적 중입니다.

## rePIU v0.0.204

Changes since the previous release, **v0.0.203** (issue #5). **The in-game `Tab` OSD now opens with the OpenGL
renderer drawing the picture, and warns when it is a software renderer.**

### Resolved issues

| Issue | Summary | Commit |
|---|---|---|
| [#5](https://github.com/nworkers/rePIU/issues/5) | The OpenGL renderer in the in-game OSD | `7edcfa2` |

### New

**A Renderer section in the OSD (#5).** The top of the OSD opened with `Tab` shows:

* The renderer (for example `NVIDIA GeForce RTX 4090/PCIe/SSE2`), its vendor and the OpenGL version.
* The SDL video driver: `windows` on Windows, `x11` or `wayland` on Linux, noting when the engine chose Mesa's D3D12
  driver on WSL.
* **A software renderer such as llvmpipe, softpipe, swrast, GDI Generic (Windows without a GPU driver), WARP or
  SwiftShader is shown in red with "Software rendering: no 3D acceleration".** If the game runs unusually slowly, look
  here first.

It only displays; no GL call is added. The log gains one line, `GL vendor/version/video driver/software: …`, next to the
existing `GL renderer:` line.

### Verified

| Configuration | Check |
|---|---|
| Win32 x86 Release | build, `repiu_core_probe` and `repiu_aot_probe --gl-renderer-identity`, the OSD captured in pumpit1 (RTX 4090, `windows`) |
| Linux x64 Debug (WSL) | build, the whole `repiu_core_probe` passes, the warning captured in pumpit1 with `GALLIUM_DRIVER=llvmpipe` (`x11`) |
| Win32 x86 Debug (CI) | build and probes |

### Known

* The software check is a name list; a software renderer not on it shows its name without the warning.
* This feature was not run on Linux i386 or under Wayland (the code is the same).
* v0.0.203's known issues remain: i386 on Wayland (NVIDIA) failing to create its window
  ([#7](https://github.com/nworkers/rePIU/issues/7)) and the Win32 Release core probe's `stack_bridge_contract`
  ([#8](https://github.com/nworkers/rePIU/issues/8)). The intermittent Linux x64 `host_thread_interrupt` failure in the
  release CI ([#12](https://github.com/nworkers/rePIU/issues/12)) is being tracked.
