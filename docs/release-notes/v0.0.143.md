## rePIU v0.0.143

이전 릴리스 **v0.0.136** 이후의 변경입니다. 이번 구간의 중심은 **성능**입니다 — pumpit2
gameplay 기준 **69.3 → 107.2 fps (+54.7%)**.

### ⚠️ 실행 파일 이름이 바뀌었습니다

`repiu_loader_win32.exe` → **`repiu.exe`**. 스크립트나 바로가기가 옛 이름을 가리키고
있다면 갱신하십시오.

### 성능

| 항목 | 결과 |
|---|---|
| **inline cache 패치의 스레드 왕복 제거** | **fps +54.7%** (69.3 → 107.2). 간접 call/jump 미스마다 14바이트를 쓰려고 워커 스레드를 깨우고 기다리던 것을 게스트 스레드가 직접 하도록 바꿨습니다. 프레임당 약 350회였고, 게스트 스레드 표본의 30.4%가 그 대기였습니다 |
| **Glide setter 상태 생략** | 같은 값으로 다시 부르는 setter의 host 왕복을 건너뜁니다. 현재 **생략률 89.6%**. `grDitherMode`는 호출당 비용이 95% 줄었습니다 |
| **draw 배칭** | 연속된 primitive를 모아 한 번에 제출합니다. 평균 배치 2.0 → **32.1** primitive |

세 가지 모두 기본으로 켜져 있고, 각각 환경변수로 끌 수 있습니다
(`REPIU_AOT_INLINE_CACHE_PATCH_INLINE=0`, `REPIU_GLIDE_SETTER_ELIDE=0`,
`REPIU_GLIDE_DRAW_BATCH=0`).

## rePIU v0.0.143

Everything since the previous release, **v0.0.136**. This stretch is about **performance**:
pumpit2 gameplay went from **69.3 to 107.2 frames per second, +54.7%**.

### ⚠️ The executable was renamed

`repiu_loader_win32.exe` is now **`repiu.exe`**. Update any script or shortcut that points
at the old name.

### Performance

**Removing the inline-cache patch round trip** is where the frames came from: **+54.7%**.
Every indirect call/jump cache miss writes fourteen bytes into the code cache, and the
guest thread was waking a worker thread and waiting for it to do that — roughly 350 times
per frame, holding 30.4% of the guest thread's sampled positions. The guest now patches its
own caches.

**Glide setter state elision** skips the host round trip when a setter is called with the
value already applied; 89.6% of setter calls are now elided, and `grDitherMode` costs 95%
less per call. **Draw batching** collects consecutive primitives into one submission,
raising the mean batch from 2.0 to 32.1 primitives.

All three are on by default and each has an off switch:
`REPIU_AOT_INLINE_CACHE_PATCH_INLINE=0`, `REPIU_GLIDE_SETTER_ELIDE=0` and
`REPIU_GLIDE_DRAW_BATCH=0`.

### Diagnostics

A **host crash reporter** now records the exception code, address, access kind and a
**symbolised call stack with source lines**. It earned itself immediately: a teardown crash
that five rounds of guessing had failed to find was named on the first crashing run.

The **asynchronous present axis was closed as a measurement error**. `grBufferSwap` looked
large with vsync on, but that was display wait; with vsync off it is 2.9%. The
implementation stays opt-in, kept on accuracy grounds rather than speed.

### Build and CI

OpenWatcom is pinned to an **immutable dated snapshot** instead of upstream's rolling
`Current-build`, whose asset is replaced in place so that a pinned hash expires with nothing
here changing. The toolchain moved with it and the sample baseline did not: 819 samples
build, 528 pass, **zero regressions**. And the **sample suite now builds without the
original asset tree** — it compiles its own DOS programs and never loads the game, but the
environment check demanded the assets anyway.
