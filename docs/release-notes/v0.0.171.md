## rePIU v0.0.171

이전 릴리스 **v0.0.170** 이후의 변경입니다. **소스 구조만 바뀌었고 동작은 그대로입니다.**

### 실행 엔진이 `src/engine/`으로 나왔습니다

`AGENTS.md`는 플랫폼 종속 코드를 `src/platform/{win32,linux,web}/`에 두라고 정합니다.
그런데 **플랫폼 공용 실행 엔진이 `src/platform/win32/` 안에 있었고 Linux가 그것을
컴파일**하고 있었습니다. 세어 보니 그 트리 119개 중 **102개가 Win32 의존이 전혀 없었습니다.**

| | 전 | 후 |
|---|---:|---:|
| `src/platform/win32/` | 119 | **6** (Linux 대응물이 있는 백엔드) |
| `src/engine/` | — | **113** |
| `include/repiu/platform/win32/` | 46 | **1** |
| `include/repiu/engine/` | — | **46** |

### 헤더 경로와 네임스페이스가 바뀝니다 — 호환성 주의

```
include "repiu/platform/win32/foo.h"   ->  include "repiu/engine/foo.h"
repiu::platform::win32::Bar            ->  repiu::engine::Bar
```

이 헤더를 쓰는 코드가 있으면 고쳐야 합니다. 백엔드(`repiu::platform`)는 바뀌지 않았습니다.

### 의존이 한 방향이 됐습니다

이전에는 `execution_trampoline.cpp`가 `#include "win32_thread_api.h"`로 **백엔드의 소스
디렉터리**를 직접 들여다봤습니다. 그 헤더를 공개 헤더로 올려, 이제 엔진은
`include/repiu/platform/win32/`를 통해서만 백엔드를 봅니다.

### 알려진 것

- **동작 변경은 없습니다.** Linux·Windows 빌드와 probe·샘플 회귀로 확인했습니다.
- **wasm 구성은 검증하지 못했습니다** — 이 환경에 Emscripten이 없습니다.
- 파일·심볼 이름의 `Win32`는 그대로입니다(`aot_code_cache_win32.cpp`에는 Win32 코드가
  없습니다). `src/host/win32/main.cpp`도 그대로입니다. 둘 다 별도 작업입니다.

## rePIU v0.0.171

Changes since **v0.0.170**. **Source layout only; behaviour is unchanged.**

### The execution engine moved to `src/engine/`

`AGENTS.md` puts platform-specific code under `src/platform/{win32,linux,web}/`. The
platform-neutral execution engine was living under `src/platform/win32/` and Linux was compiling it.
Counted, **102 of the 119 files there had no Win32 dependency at all.**

| | Before | After |
|---|---:|---:|
| `src/platform/win32/` | 119 | **6** (the backends with a Linux counterpart) |
| `src/engine/` | — | **113** |
| `include/repiu/platform/win32/` | 46 | **1** |
| `include/repiu/engine/` | — | **46** |

### Header paths and the namespace change — a compatibility break

```
include "repiu/platform/win32/foo.h"   ->  include "repiu/engine/foo.h"
repiu::platform::win32::Bar            ->  repiu::engine::Bar
```

Anything including those headers needs updating. The backends (`repiu::platform`) are unchanged.

### The dependency now runs one way

`execution_trampoline.cpp` used to reach the backend with
`#include "win32_thread_api.h"`, reading a backend's **private source tree**. That header is public
now, so the engine sees a backend only through `include/repiu/platform/win32/`.

### Known

- **No behaviour change.** Confirmed by Linux and Windows builds, the probe, and the sample
  regression.
- **The wasm configuration is unverified** -- Emscripten is not installed in this environment.
- File and symbol names still carrying `Win32` are untouched (`aot_code_cache_win32.cpp` has no
  Win32 code in it), as is `src/host/win32/main.cpp`. Both are separate tasks.
