## rePIU v0.0.214

이전 릴리스 **v0.0.213** 이후의 변경입니다(issue #45, #34 후속). **게임 중 OSD에서 전체 화면과 화면 비율을
바꾸고, 그 선택이 다음 실행까지 남습니다.** 런처에서는 게임패드 `A`로 게임을 시작할 수 있습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#45](https://github.com/reexec/rePIU/issues/45) | OSD·런처의 전체 화면·비율 유지 옵션, `cfg\repiu.ini`에 저장 | `f21ac2e` |
| [#34](https://github.com/reexec/rePIU/issues/34) (후속) | 런처 롬셋 목록에서 게임패드 `A`로 시작 | `f21ac2e` |

### 바뀐 것

**전체 화면과 비율 유지.** `Tab` OSD 맨 위에 "Fullscreen"과 "Keep aspect ratio"가 생겼습니다. 비율 유지는
기본으로 켜져 있어 지금처럼 4:3 그림 둘레에 검은 띠를 두고, 끄면 비율을 무시하고 창이나 화면을 꽉 채웁니다.
창 모드에도 같은 규칙이 적용됩니다.

| 방법 | 지속 |
|---|---|
| 게임 중 `Tab` OSD, `Alt+Enter`, 더블 클릭 | 바꾸는 즉시 `cfg\repiu.ini`의 `[Video] fullscreen`·`keep_aspect`에 저장 |
| 런처 Options 맨 위의 두 체크박스 | 같은 키 |
| `REPIU_GLIDE_FULLSCREEN`, `REPIU_GLIDE_KEEP_ASPECT` | 그 실행 (저장값보다 우선) |

다음 실행은 저장한 상태로 시작합니다. 런처 창도 두 값을 따릅니다. 전체 화면으로 열리고, 런처에서는
`Alt+Enter`로 바꾸며, 비율 유지가 켜져 있으면 런처 화면을 가운데에 두고 둘레를 검게 둡니다.
런처 Options 순서는 Fullscreen, Keep aspect ratio, vsync, Full-precision textures, Screen shader, Sound gain입니다.

**런처에서 게임패드로 시작.** 롬셋 목록에서 D-pad로 고른 뒤 `A`를 누르면 Enter처럼 시작합니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Linux x64·i386 Release | 빌드, core probe(letterbox의 늘림 사각형, 런처 설정의 두 키 포함) |
| Win32 | CI Debug 빌드(모든 타깃), `repiu_glide_issue_probe`, `repiu_aot_probe --timer-safe-point`. core·런처 probe와 실행은 하지 않음 |
| 실제 실행(Linux x64, x11) | OSD 전환마다 한 번씩 저장(14/14), 저장값으로 시작, 창을 닫을 때 전체 화면 해제는 저장 안 함, 런처 체크박스·창·Options 순서, 패드 `A` 시작 — 사용자가 화면으로 확인 |

### 알려진 것

* i386 빌드에서는 게임을 실행해 보지 않았습니다(빌드와 core probe만). 바뀐 코드는 아키텍처 공용입니다.
* Wayland 비디오 드라이버에서의 전환은 확인하지 않았습니다(실행은 모두 x11).
* 런처로 시작한 게임에서 OSD로 바꾼 값이 돌아온 런처 화면에 반영되는지는 따로 확인하지 않았습니다.

## rePIU v0.0.214

Changes since **v0.0.213** (issue #45, a #34 follow-up). **Fullscreen and the aspect ratio can be switched from
the in-game OSD, and the choice lasts to the next run.** In the launcher, a gamepad's `A` starts a game.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#45](https://github.com/reexec/rePIU/issues/45) | Fullscreen and keep-aspect options in the OSD and launcher, stored in `cfg\repiu.ini` | `f21ac2e` |
| [#34](https://github.com/reexec/rePIU/issues/34) (follow-up) | A gamepad's `A` starts a ROM set from the launcher list | `f21ac2e` |

### Changed

**Fullscreen and keep aspect ratio.** The top of the `Tab` OSD now has "Fullscreen" and "Keep aspect ratio". Keep
aspect is on by default, keeping today's 4:3 picture with black bars; off, it ignores the ratio and fills the window
or screen, windowed mode included. A change from the OSD, `Alt+Enter` or a double click is stored at once as
`[Video] fullscreen` and `keep_aspect` in `cfg\repiu.ini`; the two checkboxes at the top of the launcher's Options
use the same keys; `REPIU_GLIDE_FULLSCREEN` and `REPIU_GLIDE_KEEP_ASPECT` win over the stored values for that run.
The next run starts the way it was left. The launcher window follows both values too: it opens fullscreen,
switches with `Alt+Enter`, and with keep aspect on is drawn centred with black around it. The launcher's Options
now read Fullscreen, Keep aspect ratio, vsync, Full-precision textures, Screen shader, Sound gain.

**Starting from the launcher with a gamepad.** On the ROM set list, choose with the D-pad and press `A` to start,
as Enter does.

### Verified

* Linux x64 and i386 Release: builds; the core probe, including the letterbox probe's stretch case and the
  launcher settings' two keys.
* Win32: a CI Debug build of every target, `repiu_glide_issue_probe` and `repiu_aot_probe --timer-safe-point`; the core and launcher probes and a run were not done on Win32.
* Real runs (Linux x64, x11), confirmed on screen by the user: one store per OSD switch (14/14), the stored state
  restored at start, leaving fullscreen on close not stored, the launcher's checkboxes, window and Options order,
  and starting with the pad's `A`.

### Known

* No game was run on the i386 build (build and core probe only); the changed code is architecture-neutral.
* Switching under the Wayland video driver was not checked (every run used x11).
* Whether an OSD change in a game started from the launcher shows in the launcher it returns to was not checked
  separately.
