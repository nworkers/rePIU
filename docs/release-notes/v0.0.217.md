## rePIU v0.0.217

이전 릴리스 **v0.0.216** 이후의 변경입니다(issue #55). **게임패드로 OSD를 열고 조작합니다.** 키보드 없는
스팀덱에서도 전체 화면, 비율, 셰이더, 텍스처 같은 게임 중 설정을 바꿀 수 있습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#55](https://github.com/reexec/rePIU/issues/55) | 게임패드로 OSD 열기와 조작(LT+RT+Y) | `33eba35` |

### 바뀐 것

**게임패드 OSD.** 한 패드에서 **LT + RT + Y**를 함께 누르면 `Tab`처럼 OSD가 열리고 닫힙니다. 열려 있는 동안은
패드로 조작합니다.

| 패드 | 동작 |
|---|---|
| D-pad | 항목 이동 |
| `A` | 체크박스 바꾸기, 메뉴(셰이더 등) 열기·고르기 |
| `B` | 열린 메뉴가 있으면 메뉴만 닫고, 없으면 OSD를 닫음 |
| LT + RT + Y | OSD 닫기 |

OSD가 열려 있는 동안 **패드 입력은 게임에 가지 않고**, 열 때 눌려 있던 게임 입력은 떼어진 것으로 처리합니다.
닫을 때 누르고 있던 버튼(예: 닫으려고 누른 `B` = 기본 우하 발판)은 뗄 때까지 게임에 가지 않습니다. 키보드는
지금처럼 OSD가 열려 있어도 게임으로 갑니다. 스팀덱 사용 순서는 [런처 업데이트 가이드](../guides/launcher-update.md)에
있습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Linux x64·i386 Release | 빌드, core probe(새 `host_pad_input_osd_chord` 포함) |
| Win32 | CI Debug 빌드와 probe |
| 실제 패드(Xbox Series X, Linux x64) | LT+RT+Y로 두 번 열고 닫음, 패드로 비율 유지와 셰이더를 바꿈, 열린 동안 게임에 간 패드 입력 0건, 닫은 `B`가 게임에 새지 않음 |

### 알려진 것

* 스팀덱 실기에서는 확인하지 않았습니다.
* `Tab`으로 연 OSD도 같은 규칙이라, 열려 있는 동안에는 패드로 게임을 할 수 없습니다(키보드는 됨).

## rePIU v0.0.217

Changes since **v0.0.216** (issue #55). **A gamepad opens and drives the OSD**, so in-game settings such as
fullscreen, aspect, shader and textures can be changed on a Steam Deck with no keyboard.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#55](https://github.com/reexec/rePIU/issues/55) | Open and drive the in-game OSD with a gamepad (LT+RT+Y) | `33eba35` |

### Changed

**Gamepad OSD.** Pressing **LT + RT + Y** together on one pad opens and closes the OSD as `Tab` does. While it is
open the pad drives it: the D-pad moves between items, `A` toggles a checkbox or opens and picks from a menu (the
shader, for one), `B` closes an open menu or otherwise the OSD, and LT + RT + Y closes it too. Meanwhile **pad
input does not reach the game**, and game inputs held as it opens are released; a button still held as it closes
(such as the `B` that closed it, the down-right panel by default) stays away from the game until released. The
keyboard still reaches the game while the OSD is open. Steam Deck steps are in the
[launcher update guide](../guides/launcher-update.md).

### Verified

* Linux x64 and i386 Release: builds and the core probe, including the new `host_pad_input_osd_chord`.
* Win32: the CI Debug build and probes.
* A real pad (Xbox Series X, Linux x64): opened and closed twice with LT+RT+Y, keep-aspect and the shader changed
  with the pad, no pad input reached the game while it was open, and the closing `B` did not leak into the game.

### Known

* Not checked on a real Steam Deck.
* An OSD opened with `Tab` follows the same rule, so the pad cannot play while it is open (the keyboard can).
