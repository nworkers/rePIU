## rePIU v0.0.208

이전 릴리스 **v0.0.207** 이후의 변경입니다(issue #22). **기본으로 꺼진 채 채택되지 않은
실험 기능 13개를, 그것을 켜던 환경 변수와 함께 지웠습니다.** 아무 변수도 주지 않은 실행의
동작은 v0.0.207과 같습니다.

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#22](https://github.com/reexec/rePIU/issues/22) | 버려진 옵트인 실험의 기능과 스위치 삭제(환경 변수 토글 정리 2번 묶음) | `b8666c5` |

### 바뀐 것

**더 이상 읽지 않는 환경 변수 14개.** 아래 변수를 설정해도 아무 효과가 없습니다. 켜면
동작하던 실험 기능 자체가 없어졌습니다.

* AOT-DBT: `REPIU_AOT_DBT_POST_HLE_TRANSLATE`, `REPIU_AOT_DBT_SEGMENT_OVERRIDE_DISPATCH`,
  `REPIU_AOT_DBT_INDIRECT`, `REPIU_AOT_DBT_CALL_STEP`(간접 디스패치에서만 쓰이던 진단)
* native: `REPIU_NATIVE_REGION`, `REPIU_NATIVE_LINEAR_SPAN_CACHE`,
  `REPIU_NATIVE_LINEAR_SPAN_WRITES`, `REPIU_NATIVE_LINEAR_SPAN_JUMPS`,
  `REPIU_AOT_RETIRED_SPAN_REENTRY` (`REPIU_NATIVE_LINEAR_SPAN`은 그대로 동작합니다)
* 예전 동작을 되살리던 스위치: `REPIU_AOT_SEGMENT_WRITE_BLOCKS_RESUME`,
  `REPIU_AOT_QUARANTINE_FIRST_WRITE`, `REPIU_AOT_QUARANTINE_ON_GENERATION_FAILURE`,
  `REPIU_AOT_STRICT_SPANNING_ENTRY`, `REPIU_AOT_PATCH_WIDE_PROTECT`

**진단 출력 형식이 바뀌었습니다.** 지운 값은 기본 실행에서 항상 0이었습니다.

* `[repiu-live]` 줄에서 `region=`, `span_cache=`, `span_jump=`, `retired_span=`가 빠지고
  `span_write=`는 값 하나(fault로 끝난 span 수)가 됩니다.
* 종료 로그에서 span cache·jump, retired span, 간접 디스패치, call-step, segment-override
  관련 줄이 빠지고, `native linear span write …` 줄은 `native linear span write
  fault-cancel: N`이 됩니다. `aot reentry cycles/count/share` 줄에서 `native-span` 열이
  빠집니다.
* Win32 supervisor 줄의 `retired_span=`가 빠지고, 공유 live telemetry 버전이 24가 됩니다.
  — 이 형식을 읽는 자체 스크립트가 있다면 함께 고쳐야 합니다.

**스크립트.** 이 실험만을 비교하던 Win32 A/B 스크립트 7개(`task283`~`task287`, `task413`,
`benchmark_native_linear_span.ps1`)를 지웠습니다.

**문서.** `ARCHITECTURE.md`의 해당 절을 삭제된 기록으로 고치고, pumpit3 멈춤 가이드에는
arena 낙하 원인을 이제 Task 417 이전 빌드로만 재현할 수 있다고 적었습니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Linux x64 Release | 빌드, core probe(v0.0.207과 같은 결과), 16개 롬셋 30초 스모크(fault 0)와 v0.0.207 빌드와의 교대 재실행(프레임 ±5% 이내), pumpitea 90초 교대 두 쌍(로고 다음 공백 1.18·1.21초 / 1.24·1.21초) |
| Linux i386 Release | 빌드, core probe, 16개 롬셋 30초 스모크(fault 0)와 교대 재실행(프레임 ±3% 이내), pumpitea 90초 교대(프레임 5134 / 5166) |

### 알려진 것

* **Win32 빌드는 확인하지 않았습니다.** 바뀐 Win32 전용 파일(supervisor, dispatch thunk,
  `repiu_aot_probe`의 selector guard·native span probe)은 Win32 빌드에서 확인이 필요합니다.
* Linux 스모크에서 프레임 수가 실행마다 크게 흔들렸습니다. 낮은 쪽은 모두 창이 가려졌을 때
  vsync swap이 막혀 fps가 1.0에 묶이는 기존 상태(#6)였고, v0.0.207 빌드에서도 같은 빈도로
  나타났습니다.

## rePIU v0.0.208

Changes since **v0.0.207** (issue #22). **Thirteen experimental features that stayed off and
were never adopted are gone, together with the environment variables that turned them on.**
A run with nothing set behaves as v0.0.207 did.

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#22](https://github.com/reexec/rePIU/issues/22) | Delete the abandoned opt-in experiments and their switches (environment toggle cleanup, group 2) | `b8666c5` |

### Changed

**Fourteen variables are no longer read**; setting them has no effect because the experiments
they enabled are gone: `REPIU_AOT_DBT_POST_HLE_TRANSLATE`,
`REPIU_AOT_DBT_SEGMENT_OVERRIDE_DISPATCH`, `REPIU_AOT_DBT_INDIRECT`, `REPIU_AOT_DBT_CALL_STEP`
(a diagnostic only indirect dispatch used), `REPIU_NATIVE_REGION`,
`REPIU_NATIVE_LINEAR_SPAN_CACHE`, `REPIU_NATIVE_LINEAR_SPAN_WRITES`,
`REPIU_NATIVE_LINEAR_SPAN_JUMPS`, `REPIU_AOT_RETIRED_SPAN_REENTRY` (`REPIU_NATIVE_LINEAR_SPAN`
still works), and the switches that restored older behavior:
`REPIU_AOT_SEGMENT_WRITE_BLOCKS_RESUME`, `REPIU_AOT_QUARANTINE_FIRST_WRITE`,
`REPIU_AOT_QUARANTINE_ON_GENERATION_FAILURE`, `REPIU_AOT_STRICT_SPANNING_ENTRY`,
`REPIU_AOT_PATCH_WIDE_PROTECT`.

**Diagnostic output changed format**; every removed value was always zero in a default run.
The `[repiu-live]` line drops `region=`, `span_cache=`, `span_jump=` and `retired_span=`, and
`span_write=` carries one value (spans ended by a fault). The final log drops the span
cache/jump, retired span, indirect dispatch, call-step and segment-override lines, the
`native linear span write …` line becomes `native linear span write fault-cancel: N`, and the
`aot reentry cycles/count/share` lines lose their `native-span` column. The Win32 supervisor
line drops `retired_span=` and shared live telemetry becomes version 24 — update any script of
your own that reads these formats.

**Scripts**: the seven Win32 A/B scripts that compared only these experiments (`task283`–
`task287`, `task413`, `benchmark_native_linear_span.ps1`) are deleted.

**Docs**: the affected `ARCHITECTURE.md` sections now record the deletion, and the pumpit3
stall guide notes that the arena fall-through now reproduces only on a build from before
Task 417.

### Verified

* Linux x64 Release: build; core probe (same results as v0.0.207); a 16-romset 30 s smoke
  (zero faults) with reruns alternating the v0.0.207 build (frames within ±5%); two
  alternating 90 s pumpitea pairs (post-logo gap 1.18/1.21 s vs 1.24/1.21 s).
* Linux i386 Release: build; core probe; a 16-romset 30 s smoke (zero faults) with
  alternating reruns (frames within ±3%); an alternating 90 s pumpitea pair (5134 / 5166
  frames).

### Known

* **The Win32 build was not checked.** The changed Win32-only files (the supervisor, the
  dispatch thunks, and the selector guard and native span probes of `repiu_aot_probe`) need a
  Win32 build.
* Frame counts in the Linux smoke swung widely from run to run. The low ones were all the
  existing state in which a covered window blocks the vsync swap and pins fps at 1.0 (#6), and
  the v0.0.207 build showed it as often.
