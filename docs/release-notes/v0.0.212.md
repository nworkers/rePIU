## rePIU v0.0.212

이전 릴리스 **v0.0.211** 이후의 변경입니다(issue #34). **게임패드와 조이스틱(USB 발판 포함)으로
게임과 런처를 조작할 수 있습니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#34](https://github.com/nworkers/rePIU/issues/34) | 게임과 런처의 게임패드·조이스틱 입력 | `6e9cba3` |

### 바뀐 것

**표준 게임패드는 설정 없이 동작합니다.** 먼저 연결한 패드가 1P, 두 번째가 2P입니다.

| 입력 | 게임패드 |
|---|---|
| 좌상 / 우상 발판 | LB / RB |
| 좌하 발판 | D-pad 아래, D-pad 왼쪽 |
| 우하 발판 | B, D-pad 오른쪽 |
| 가운데 발판 | A, Start |
| 코인(COIN1) | Back |
| CLEAR | 오른쪽 스틱 클릭 |

TEST와 SERVICE는 게임 중 실수로 운영자 메뉴에 들어가지 않도록 게임패드 기본값이 없습니다(키보드
F1·F2).

**배정을 바꾸거나 다른 장치를 쓰려면** `cfg/<롬셋>.ini`의 `[Input]` 값에 키 이름과 섞어 씁니다.
표준 매핑이 없는 장치(USB 발판 등)는 버튼·hat 번호로 겁니다.

```ini
[Input]
P1_CENTER = S, Pad1_A, Joy1_Button5
P1_UP_LEFT = Q, Joy1_Hat1Up
```

장치는 연결한 순서대로 번호(`Pad1`~`Pad4`, `Joy1`~`Joy8`)를 받고, 연결되면 stderr에
`[repiu-pad] Pad1 connected: <이름>`이 찍힙니다. 키와 게임패드로 같은 입력을 누르면 둘 다 뗄 때까지
눌린 상태가 유지되고, 창이 포커스를 잃으면 게임패드 입력도 뗀 것으로 처리합니다. 전체 이름 목록은
[설정 파일 가이드](../guides/romset-config-files.md) §6.1에 있습니다.

**런처도 게임패드로 조작합니다.** D-pad로 옮기고 A로 고릅니다.

**기존 설정 파일:** 입력 줄을 직접 적어 두었다면 그 줄이 게임패드 기본값까지 대신합니다. 주석 상태로
둔 줄은 새 기본값을 따릅니다. 새로 생성되는 설정 파일의 주석에는 게임패드 이름 목록이 들어갑니다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 Release | 빌드, 새 probe `host_pad_input`, 설정 probe 94개, `repiu_aot_probe` 전체 체인, core probe 전체 |
| Linux x64 Release | 빌드, core probe 전체 |
| 실제 장치 | 사용자가 표준 게임패드로 게임·런처와 기본 배치를 확인 |

### 알려진 것

* 아날로그 스틱 방향과 조이스틱 축은 지원하지 않습니다.
* 발판형 조이스틱(`Joy<N>_` 이름)은 실제 장치로 확인하지 않았습니다.
* Linux i386 빌드는 확인하지 않았습니다.

## rePIU v0.0.212

Changes since **v0.0.211** (issue #34). **Gamepads and joysticks, USB dance pads included, now drive
the game and the launcher.**

### Resolved issues

| issue | Summary | Commit |
|---|---|---|
| [#34](https://github.com/nworkers/rePIU/issues/34) | Gamepad and joystick input for the game and the launcher | `6e9cba3` |

### Changed

**A standard gamepad works with no configuration**: the first one connected is P1 and the second
P2. LB and RB are the upper-left and upper-right panels, D-pad down and left the lower-left one, B
and D-pad right the lower-right one, A and Start the center, Back inserts a coin, and the right
stick click is CLEAR. TEST and SERVICE have no gamepad default, so a pad cannot open the operator
menus by accident (they stay on F1 and F2).

**To change the layout or use another device**, mix pad names with key names in the `[Input]` values
of `cfg/<rom-set>.ini`; devices without a standard mapping (USB dance pads and the like) are bound
by button or hat number, as in `P1_CENTER = S, Pad1_A, Joy1_Button5` or
`P1_UP_LEFT = Q, Joy1_Hat1Up`. Devices are numbered in connection order (`Pad1`–`Pad4`,
`Joy1`–`Joy8`) and announce themselves on stderr as `[repiu-pad] Pad1 connected: <name>`. An input
held by both a key and a pad stays held until both release, and losing window focus releases pads
too. The full list of names is in §6.1 of the [config file guide](../guides/romset-config-files.md).

**The launcher works with a gamepad too**: move with the D-pad, choose with A.

**Existing config files**: an input line you wrote yourself replaces the gamepad default as well;
lines left commented out follow the new defaults. Newly generated config files list the gamepad
names in their comments.

### Verified

* Win32 Release: build, the new `host_pad_input` probe, 94 config probe checks, the full
  `repiu_aot_probe` chain and the full core probe.
* Linux x64 Release: build and the full core probe.
* Real hardware: the user checked the game, the launcher and the default layout on a standard
  gamepad.

### Known

* Analog stick directions and joystick axes are not supported.
* Dance-pad joysticks (`Joy<N>_` names) were not tried on a real device.
* The Linux i386 build was not checked.
