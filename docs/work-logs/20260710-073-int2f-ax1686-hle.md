# INT 2Fh AX=1686h HLE 작업 로그

## 변경 내용

`piu_1st`가 runtime arena 확장 이후 도달한 `INT 2Fh AX=1686h`를 trace 경로에서도 처리하도록 추가했다.

기존 일반 DOS HLE 경로에는 `HandleDosInterrupt2F`와 `AX=1686h` 최소 응답이 있었지만, single-step trace pre-handler는 `HandleTracedDosInterrupt21`만 호출하고 있었다. 따라서 `CD 2F`가 일반 HLE 경로로 들어가기 전에 예외로 관측되었다.

이번 작업에서는 다음을 변경했다.

* `HandleTracedDosInterrupt2F`를 추가하고 trace pre-handler에서 호출한다.
* `AX=1686h`에 대해 Windows enhanced mode / external DPMI host 비활성 정책으로 기존 최소 응답을 사용한다.
  * `AX=0000h`
  * `EIP += 2`
* interrupt 관측에 마지막 `AX` 필드를 추가했다.
* loader는 마지막 DOS interrupt `AX`를 출력한다.
* `scripts/test_all.ps1`는 `INT 2Fh AX=1686h` 처리 후 다음 blocker를 확인하도록 갱신했다.

## 결과

`INT 2Fh AX=1686h`는 처리되었고, `piu_1st`는 다음 blocker로 진행했다.

새 관측은 다음과 같다.

* last handled DOS interrupt vector: `0x2F`
* last handled DOS interrupt AH: `0x16`
* last handled DOS interrupt AX: `0x1686`
* next exception address: `0x020FCDF2`
* next instruction: `CD 31`
* exception EAX: `0x00000400`

따라서 다음 작업은 trace 경로에서 `INT 31h AX=0400h` DPMI 호출을 연결하는 것이다. 일반 HLE 경로에는 이미 `HandleDpmiInterrupt31`의 `AX=0400h` 최소 응답이 있으므로, 이번 작업과 비슷하게 trace pre-handler에 `INT 31h`를 연결하는 방향이 유력하다.

## 검증

* `cmd /c scripts\build_win32_x86.bat`
  * 결과: 성공
  * 참고: 기존 spdlog code page 경고는 유지됨
* `build\win32_x86_debug\Debug\repiu_loader_win32.exe piu_1st`
  * 결과: 성공
  * 확인: `INT 2Fh AX=1686h` 처리 후 `INT 31h AX=0400h` blocker 도달
* `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1`
  * 결과: 성공

# INT 2Fh AX=1686h HLE Work Log

## Changes

Added trace-path handling for `INT 2Fh AX=1686h`, reached by `piu_1st` after runtime arena expansion.

The general DOS HLE path already had `HandleDosInterrupt2F` and a minimal `AX=1686h` response, but the single-step trace pre-handler only called `HandleTracedDosInterrupt21`. As a result, `CD 2F` was observed as an exception before it could reach the general HLE path.

This task changed the following:

* Added `HandleTracedDosInterrupt2F` and called it from the trace pre-handler.
* Used the existing minimal response for `AX=1686h`, following the Windows enhanced mode / external DPMI host inactive policy.
  * `AX=0000h`
  * `EIP += 2`
* Added the last interrupt `AX` observation field.
* Made the loader print the last DOS interrupt `AX`.
* Updated `scripts/test_all.ps1` to check the next blocker after `INT 2Fh AX=1686h` is handled.

## Result

`INT 2Fh AX=1686h` is now handled, and `piu_1st` progressed to the next blocker.

New observations:

* last handled DOS interrupt vector: `0x2F`
* last handled DOS interrupt AH: `0x16`
* last handled DOS interrupt AX: `0x1686`
* next exception address: `0x020FCDF2`
* next instruction: `CD 31`
* exception EAX: `0x00000400`

So the next task is to connect trace-path handling for `INT 31h AX=0400h`. The general HLE path already has a minimal `HandleDpmiInterrupt31` response for `AX=0400h`, so the likely fix is similar: call the INT 31h handler from the trace pre-handler.
