# INT 21h AH=3Fh 파일 읽기 HLE 작업 로그

## 결과

DOS VFS open handle에 file offset을 추가하고, `INT 21h AH=3Fh` 파일 읽기 HLE를 구현했다. 열린 host file을 binary mode로 열고 현재 offset에서 요청 바이트 수만큼 읽은 뒤 guest buffer에 기록한다. 성공 시 carry flag를 clear하고 `AX`에 실제 읽은 바이트 수를 반환한다.

일반 DOS interrupt handler와 traced DOS interrupt handler 양쪽에 `AH=3Fh` 처리를 연결했다. Win32 loader 로그에는 마지막 DOS read handle, 요청 바이트 수, 실제 읽은 바이트 수, guest buffer, 결과를 출력한다.

## 관찰

`piu_1st`는 `intro.ani`를 handle `0x0005`로 연 뒤 `AH=3Fh` read를 3번 수행했다. 마지막 관측 read는 요청 바이트 수와 실제 읽은 바이트 수가 모두 `0`인 성공 처리였다.

이 작업 후 기존 `AH=3Fh` 중단점은 통과했다. 다음 blocker는 relocated base + `0x000F79D4`의 `CD 21`이며, 예외 시점 `EAX=0x00004201`, `EBX=0x00000005`, `ECX=0`, `EDX=0`이다. 이는 handle `0x0005`에 대한 `INT 21h AH=42h AL=01h` file seek 요청으로 보인다.

## 검증

다음 명령으로 검증했다.

* `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`

결과는 통과했다. Win32 x86 빌드 중 third-party `spdlog` header의 기존 코드 페이지 경고 `C4819`가 계속 출력되지만 빌드 실패는 아니다.

# INT 21h AH=3Fh file read HLE work log

## Result

Added a file offset to DOS VFS open handles and implemented `INT 21h AH=3Fh` file read HLE. The handler opens the host file in binary mode, reads the requested byte count from the current offset, and writes the data to the guest buffer. On success it clears carry and returns the actual byte count in `AX`.

`AH=3Fh` handling was wired into both the normal DOS interrupt handler and the traced DOS interrupt handler. The Win32 loader log now prints the last DOS read handle, requested byte count, actual byte count, guest buffer, and result.

## Observation

`piu_1st` opened `intro.ani` as handle `0x0005` and performed three `AH=3Fh` reads. The last observed read had requested bytes and actual bytes both equal to `0`, and succeeded.

After this task, the previous `AH=3Fh` blocker is passed. The next blocker is `CD 21` at relocated base + `0x000F79D4`, with exception-time `EAX=0x00004201`, `EBX=0x00000005`, `ECX=0`, and `EDX=0`. This appears to be `INT 21h AH=42h AL=01h` file seek for handle `0x0005`.

## Verification

Verified with:

* `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`

The verification passed. The Win32 x86 build still reports the existing third-party `spdlog` code-page warning `C4819`, but it is not a build failure.
