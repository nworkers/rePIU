# INT 21h AH=35h 인터럽트 벡터 조회 작업 로그

## 결과

`INT 21h AH=35h`를 DOS HLE에 추가했다. 현재 HLE는 실제 interrupt vector table을 유지하지 않으므로, 최소 응답으로 `ES:BX = 0000:0000`을 반환하고 carry flag를 clear한다.

일반 DOS interrupt handler와 traced DOS interrupt handler 양쪽에 같은 처리를 추가했다.

## 관측

`piu_1st`는 기존 중단점인 `INT 21h AH=35h AL=09h`를 통과했다. 다음 중단점은 relocated base + `0x000F4987`의 `CD 21`이며, `EAX=0x00002509`이다.

이는 `INT 21h AH=25h AL=09h`, 즉 interrupt 09h vector 설정 요청이다. 원본이 keyboard interrupt vector를 조회한 뒤 새 vector를 설치하려는 흐름으로 보인다.

## 검증

* 통과: `cmd /c scripts\build_win32_x86.bat`
* 통과: `build\win32_x86_debug\Debug\repiu_loader_win32.exe piu_1st`
* 통과: `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`
* 참고: Win32 x86 빌드 중 서드파티 `spdlog` 헤더의 기존 `C4819` 경고가 출력되었다.

# INT 21h AH=35h Get Vector Work Log

## Result

`INT 21h AH=35h` was added to the DOS HLE. Because the current HLE does not maintain a real interrupt vector table, the minimal response returns `ES:BX = 0000:0000` and clears carry flag.

The same behavior was added to both the normal DOS interrupt handler and the traced DOS interrupt handler.

## Observation

`piu_1st` passed the previous `INT 21h AH=35h AL=09h` blocker. The next blocker is `CD 21` at relocated base + `0x000F4987`, with `EAX=0x00002509`.

This is `INT 21h AH=25h AL=09h`, a request to set interrupt 09h vector. The original appears to query the keyboard interrupt vector and then install a new vector.

## Verification

* Passed: `cmd /c scripts\build_win32_x86.bat`
* Passed: `build\win32_x86_debug\Debug\repiu_loader_win32.exe piu_1st`
* Passed: `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`
* Note: The Win32 x86 build still emits the existing third-party `spdlog` header `C4819` warning.
