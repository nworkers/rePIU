# Task 610 작업 로그 — DPMI selector context와 allocator frontier

## 한국어

### 작업 목적

Linux x64에서 `INT 31h AX=0006` 직후 발생하던 흐름을 관찰하여 DPMI
selector context 문제와 실제 파일 구조체 allocator 실패를 분리했습니다.

### 변경 사항

* `66 8C DB`를 `MOV BX,DS`로 분류하는 x64 AOT planner probe를 추가했습니다.
* guest entry가 속한 LE object 2의 selector `0x0024`를 논리 DS로 초기화하고,
  stack object 4의 selector `0x0034`를 논리 SS로 초기화했습니다.
* DPMI `AX=0006`, segment read/store, DOS `AH=40h`, 종료 시 allocator 상태를
  `REPIU_DOS_INT_TRACE=1`에서만 기록하도록 진단을 추가했습니다.
* 진단은 원본 guest EIP 우회나 원본 실행 파일 수정 없이 유지했습니다.

### 검증 결과

재빌드 명령:

```text
cmake --build build/linux_x64_debug --target repiu_core_probe repiu -j 2
```

결과:

```text
core_probe_total=24
core_probe_failures=0
core_probe_all=true
```

최신 `pumpit2a` 실행에서 다음을 확인했습니다.

* DPMI `AX=0006`: selector `0x0024`, base `0x01010000`, `CX:DX=0x01010000`,
  CF clear.
* `CON` open: handle `0x0005`.
* `CON` write: 요청 47바이트, 실제 47바이트, DOS error `0x0000`.
* 종료: `AX=4C01h`, SIGSEGV/SIGILL 없음.
* allocator: `head=cursor=limit=0`,
  `selector_limit=memory_base=0x0158CC90`.
* allocator 요청은 8에서 `0x1000`으로 정규화되어
  `0x0158DC90` 경계 검사를 통과하지 못합니다. 따라서 현재 실행은
  `AH=4Ah` resize interrupt 이전에 원본 오류 경로로 종료합니다.

`pumpit1`도 같은 원본 오류 문구와 정상 DOS 종료까지 도달했지만,
allocator 진단 주소는 `pumpit2a` 전용이므로 다른 대상의 allocator 값은
비교하지 않았습니다. `pumpit2`는 CHD mount directory가 없어 실행하지
못했습니다.

### 결론과 다음 작업

Task610의 DPMI selector 및 `CON` 경계는 해결되었습니다. 다음 구현 과제는
DOS/4GW가 기대하는 동적 메모리 경계와 guest stack top 사이의 headroom을
runtime memory plan에 반영하는 것입니다. 임의 free-list node 주입이나
특정 guest EIP 우회는 허용하지 않습니다.

## English

### Objective

Observe the Linux x64 flow after `INT 31h AX=0006` and separate the DPMI
selector-context issue from the actual file-structure allocator failure.

### Changes

* Added an x64 AOT planner probe that classifies `66 8C DB` as `MOV BX,DS`.
* Initialized logical DS from selector `0x0024` of LE object 2 containing the
  guest entry, and logical SS from selector `0x0034` of stack object 4.
* Added opt-in diagnostics for DPMI `AX=0006`, segment reads/stores, DOS
  `AH=40h`, and allocator state at termination under
  `REPIU_DOS_INT_TRACE=1`.
* Preserved the original guest path without EIP bypasses or executable-file
  modification.

### Verification

Build command:

```text
cmake --build build/linux_x64_debug --target repiu_core_probe repiu -j 2
```

Result:

```text
core_probe_total=24
core_probe_failures=0
core_probe_all=true
```

The latest `pumpit2a` run confirmed:

* DPMI `AX=0006`: selector `0x0024`, base `0x01010000`,
  `CX:DX=0x01010000`, CF clear.
* `CON` open: handle `0x0005`.
* `CON` write: 47 requested, 47 written, DOS error `0x0000`.
* Termination: `AX=4C01h`, with no SIGSEGV or SIGILL.
* Allocator: `head=cursor=limit=0`,
  `selector_limit=memory_base=0x0158CC90`.
* The allocator normalizes request 8 to `0x1000` and rejects end address
  `0x0158DC90` at its boundary check. The run therefore reaches the original
  error path before DOS `AH=4Ah` resize.

`pumpit1` also reaches the same original error text and normal DOS termination,
but its allocator values were not compared because the diagnostic addresses
are `pumpit2a`-specific. `pumpit2` was not run because its CHD mount directory
is absent.

### Conclusion and next task

Task610 resolves the DPMI selector and `CON` boundaries. The next implementation
task is to represent the DOS/4GW dynamic-memory boundary and headroom above the
guest stack top in the runtime memory plan. Arbitrary free-list injection and
guest-EIP bypasses remain out of scope.
