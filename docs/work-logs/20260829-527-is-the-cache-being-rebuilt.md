## 526의 가설은 반증됐습니다

```
[repiu-live-aot] #4 ... reentry=454450 fallback=0
                        retired=133 quarantine=0 translate=295 sum_ok=1
```

| | 값 | 재진입 대비 |
|---|---:|---:|
| 캐시 재진입 | 454,450 | — |
| 회수된 엔트리 트랩 | **133** | 0.03% |
| 격리 | **0** | 0% |
| 동적 번역 시도 | **295** | 0.06% |

**캐시는 안정적입니다.** 295회 번역으로 만들어져 그대로 유지됩니다. "무효화·재구축되며 매번
새 INT3가 심어진다"는 그림은 틀렸습니다.

`relinked`가 디스패치당 6.09회인 것은 여전히 사실이지만, **그것으로 캐시 수명을 말할 수
없다는 것이 이번에 확인된 내용입니다.** Task 519도 같은 지점에서 같은 결론에 도달했는데,
526에서 다시 그 수를 근거로 삼았습니다.

## 계측 자체가 틀렸던 부분

526의 site 히스토그램은 여덟 자리를 각 **1회**로 보고했고, 저는 그것을 "site가 거의
재등장하지 않는다"로 읽었습니다. **계측의 성질이었습니다** — 빈 칸을 채우고 얼어붙는 구조라
기동 시점의 일회성 자리만 담고 이후를 보지 못했습니다.

번역 295회로 만든 안정된 캐시에서 38만 건이 나오면 자리는 **반드시** 반복됩니다.
그 모순이 계측을 의심할 근거였는데, 처음에는 데이터를 그대로 믿었습니다.

가장 차가운 칸을 밀어내도록 고친 뒤:

```
[repiu-live-site] #4 F54BADF0=58467 F54A8EF2=12095 F546C158=4272
                     F54A8EEC=3962 F51DC0C4=103 ...
```

| | |
|---|---|
| 최다 자리 `F54BADF0` | 58,467 / 381,105 = **15.3%** |
| 상위 4개 합 | 약 **20.4%** |

**단일 캐시 주소 하나가 후속 breakpoint의 15%를 차지합니다.**

## 이 수치의 한계

밀어낸 칸은 1부터 다시 세므로 **하한이며 정확한 순위표가 아닙니다.** 상위 4개가 약 20%라는
것은 "적어도 20%"로 읽어야 합니다. 나머지 80%가 소수의 자리에 더 몰려 있는지 넓게 퍼져
있는지는 이 sketch로 말할 수 없습니다.
