# INT 21h AH=0xFF HLE 작업 로그

## 결과

trace 기반 DOS HLE 경로를 `AH=0x30` 전용에서 `AH=0x30`/`AH=0xFF` 처리 경로로 확장했다.
`AH=0xFF`는 아직 의미를 확정하지 않고 DOS/4G 비표준 질의 후보로 기록한다.

처리 규칙은 기존 hello 전용 임시 처리와 동일하다.

* `AL = 0`
* carry flag clear
* `EIP += 2`

`piu_1st` 경로는 여전히 전체 DOS console/memory HLE를 켜지 않고, 실제 trace로 확인된 `INT 21h` 함수만 처리한다.

## 검증

* `cmd /c scripts\build_win32_x86.bat`: 성공
  * `spdlog` 외부 헤더의 MSVC C4819 경고는 유지되지만 빌드는 성공했다.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe piu_1st`: 성공
  * handled HLE trap count: `1`
  * handled DOS interrupt count: `2`
  * last handled DOS interrupt vector: `0x21`
  * last handled DOS interrupt AH: `0xFF`
  * 기존 `0x020F3954`의 `INT 21h AH=0xFF`를 통과한 뒤 다음 중단 지점 `0x020F3995`에 도달했다.
  * 다음 byte window의 focus opcode는 `0x8E`이고 bytes는 `8E D9`이다.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe dos4gw_hello`: 성공
  * stdout의 `Hello, world!` 출력 유지
  * handled DOS interrupt count: `2`
  * last handled DOS interrupt AH: `0xFF`

## 판단

`AH=0xFF`는 최소 응답으로 넘길 수 있음이 확인되었다.
다음 중단 지점 `8E D9`는 `MOV` to segment register 계열 명령이다.
따라서 다음 작업은 이 명령이 어느 segment register를 로드하는지 분류하고, Win32 user-mode에서 직접 반영할 수 없는 selector/descriptor 상태를 HLE로 어떻게 보존할지 설계하는 것이다.

# INT 21h AH=0xFF HLE Work Log

## Result

Extended the trace-based DOS HLE path from `AH=0x30` only to `AH=0x30`/`AH=0xFF`.
`AH=0xFF` is not assigned a final meaning yet; it is recorded as a DOS/4G non-standard query candidate.

The handling rule matches the existing hello-only temporary behavior.

* `AL = 0`
* clear carry flag
* `EIP += 2`

The `piu_1st` path still does not enable the whole DOS console/memory HLE path; it handles only the `INT 21h` functions confirmed by trace.

## Verification

* `cmd /c scripts\build_win32_x86.bat`: passed
  * MSVC C4819 warnings from external `spdlog` headers remain, but the build passed.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe piu_1st`: passed
  * handled HLE trap count: `1`
  * handled DOS interrupt count: `2`
  * last handled DOS interrupt vector: `0x21`
  * last handled DOS interrupt AH: `0xFF`
  * execution passed the previous `INT 21h AH=0xFF` stop at `0x020F3954` and reached the next stop at `0x020F3995`
  * the focused opcode in the next byte window is `0x8E`, with bytes `8E D9`
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe dos4gw_hello`: passed
  * Preserved `Hello, world!` on stdout
  * handled DOS interrupt count: `2`
  * last handled DOS interrupt AH: `0xFF`

## Judgment

`AH=0xFF` can be passed with the minimal response.
The next stop, `8E D9`, is a `MOV` to segment register instruction.
The next task is to classify which segment register this instruction loads and design how selector/descriptor state should be preserved in HLE because Win32 user mode cannot directly mirror that state.
