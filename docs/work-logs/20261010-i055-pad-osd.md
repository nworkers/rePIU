# 작업 로그: 게임패드로 OSD 열기와 조작 (issue #55)

설계: `docs/design/20261010-i055-pad-osd.md`
작업 지시: `docs/work-orders/20261010-i055-pad-osd.md`

## 한 일

* **입력 계층** `repiu/input/pad_osd_chord`: `IsPadOsdChordDown`(한 패드의 두 트리거와 Y),
  `PadChordEdge`(눌리는 순간 한 번), `PadGameGate`(막힘 중 0, 풀릴 때 눌린 비트는 뗄 때까지 숨김).
* **`SdlPadInput`**: 관문을 거친 마스크를 게시하고 `SetGameInputSuppressed`가 그 변화를 돌려준다.
* **백엔드**: 패드 변화를 edge로 기록하던 코드를 `RecordPadMaskChange`로 묶어 이벤트와 막힘 변화가 같은
  경로를 쓴다. 펌프 끝마다 LT+RT+Y의 가장자리로 OSD를 토글하고, 막힘을 OSD 표시 여부(Tab으로 연 경우 포함)에
  맞추며 `[repiu-pad] OSD open/closed` 로그를 남긴다.
* **OSD**: `NavEnableGamepad`, 열릴 때 포커스, 직전 프레임에 메뉴가 없을 때 B로 닫기, 안내 줄.
* **probe**: `host_pad_input_osd_chord`(조합 / 한 트리거 빠짐 / 두 패드에 나눔 / 종료 조합과 겹치지 않음,
  가장자리, 관문의 통과·막힘·숨김·해제).
* **문서**: 설계·작업 지시, README, 설정 가이드 패드 절, 스팀덱 가이드, ARCHITECTURE(OSD 입력 규칙의 예외,
  패드 절).

## 검증

| 검증 | 결과 |
|---|---|
| Linux x64·i386 Release 빌드 | 통과, 새 경고 없음 |
| core probe | 두 아키텍처 모두 `host_pad_input_osd_chord=true`, 실패 0 |
| 실제 패드(Xbox Series X, Linux x64, 런처 → pumpitpru) | LT+RT+Y로 열고 닫기 두 번. 첫 번째 열림 동안 패드로 비율 유지를 끄고 켜(둘 다 `cfg/repiu.ini`에 저장) 셰이더 콤보에서 `crt`를 고름. **열려 있는 동안 게임에 간 패드 입력은 0건**(`[repiu-input]` 없음). 닫은 직후 우하 발판 입력 없음(B가 새지 않음). 이후 COIN1·가운데 발판 정상, 종료 조합으로 게임 종료, 런처도 종료 조합으로 닫힘(새 로그 줄 확인). 사용자가 화면으로 의도대로 동작함을 확인(2026-10-10) |

## 확인하지 않은 것

* Win32 빌드(CI 예정)와 스팀덱 실기.
* 2P 패드로 연 경우(판정은 패드 번호와 무관하며 probe로만 확인).

# Work log: opening and driving the OSD with a gamepad (issue #55)

**Done.** In the input layer, `repiu/input/pad_osd_chord`: `IsPadOsdChordDown` (both triggers and Y on one pad),
`PadChordEdge` (true once as it goes down) and `PadGameGate` (zero while suppressed; bits held as it reopens stay
hidden until released). `SdlPadInput` publishes the gated mask and `SetGameInputSuppressed` returns its change.
The backend folds its pad-change-to-edges code into `RecordPadMaskChange`, so events and suppression changes take
one path; at the end of every pump it toggles the OSD on LT+RT+Y's edge, keeps suppression equal to whether the
OSD is shown (Tab included) and logs `[repiu-pad] OSD open/closed`. The OSD turns on `NavEnableGamepad`, takes
focus when opened, closes on B when no menu was open on the previous frame, and names the pad controls in its hint
line. The `host_pad_input_osd_chord` probe covers the chord, one trigger missing, a split across pads, no overlap
with the exit chord, the edge, and the gate passing, blocking, hiding and freeing. Docs: design, work order,
README, the settings guide's pad section, the Steam Deck guide, ARCHITECTURE (the OSD input rule's exception and
the pad section).

**Verified.** Linux x64 and i386 Release builds with no new warnings; the core probe reports
`host_pad_input_osd_chord=true` and no failures on both. On a real pad (Xbox Series X, Linux x64, launcher →
pumpitpru) the OSD opened and closed twice with LT+RT+Y. While it was first open the pad turned keep-aspect off and
on (both stored in `cfg/repiu.ini`) and picked `crt` from the shader combo, and **no pad input reached the game**
(no `[repiu-input]` line). Right after it closed there was no down-right press (B did not leak). COIN1 and the
center panel then worked as usual, the exit chord ended the game, and the launcher closed by the chord too (the
new log line seen). The user confirmed on screen that it works as intended (2026-10-10).

**Not checked.** The Win32 build (CI to come) and a real Steam Deck; opening it from a P2 pad (the check ignores
the pad number; probe only).
