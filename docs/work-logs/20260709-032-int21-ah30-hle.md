# INT 21h AH=0x30 HLE 작업 로그

## 결과

Win32 execution trampoline에 DOS version query HLE 플래그를 추가했다.
`piu_1st` 경로는 privileged trap HLE와 `INT 21h AH=0x30`만 처리하며, hello 샘플용 DOS console/memory HLE 전체를 켜지 않는다.

`INT 21h AH=0x30` 처리 결과는 기존 hello 경로와 같은 값을 사용한다.

* `AX = 0x0007`
* `EBX = 0`
* `ECX = 0`
* carry flag clear
* `EIP += 2`

execution attempt에는 처리된 DOS interrupt count, 마지막 interrupt vector, 마지막 DOS AH 값을 기록한다.
loader 로그도 해당 값을 출력한다.

## 검증

* `cmd /c scripts\build_win32_x86.bat`: 성공
  * `spdlog` 외부 헤더의 MSVC C4819 경고는 유지되지만 빌드는 성공했다.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe piu_1st`: 성공
  * handled HLE trap count: `1`
  * last handled HLE trap opcode: `0xFB`
  * handled DOS interrupt count: `1`
  * last handled DOS interrupt vector: `0x21`
  * last handled DOS interrupt AH: `0x30`
  * 기존 `0x020F38B5`의 `INT 21h AH=0x30`을 통과한 뒤 다음 중단 지점 `0x020F3954`에 도달했다.
  * 다음 byte window는 `66 BA 78 00 66 B8 00 FF CD 21`을 포함하므로 다음 DOS 호출은 `AX=0xFF00`, 즉 `AH=0xFF`로 보인다.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe dos4gw_hello`: 성공
  * stdout의 `Hello, world!` 출력 유지
  * handled DOS interrupt count: `1`
  * last handled DOS interrupt AH: `0x30`

## 판단

`piu_1st`의 첫 DOS service 요구사항은 DOS version query였고, 최소 HLE 처리로 통과 가능함이 확인되었다.
다음 요구사항은 `INT 21h AH=0xFF`이다.
기존 hello 전용 경로에는 `AH=0xFF`를 carry clear와 `AL=0`으로 처리하는 임시 코드가 있으나, `piu_1st` 경로에는 아직 연결하지 않았다.

다음 작업은 `AH=0xFF`의 의미를 현재 trace와 레지스터 상태 기준으로 기록하고, 필요한 최소 DOS HLE dispatcher 처리로 연결하는 것이다.

# INT 21h AH=0x30 HLE Work Log

## Result

Added a DOS version query HLE flag to the Win32 execution trampoline.
The `piu_1st` path handles only privileged trap HLE and `INT 21h AH=0x30`; it does not enable the whole DOS console/memory HLE path used by the hello sample.

`INT 21h AH=0x30` uses the same response as the existing hello path.

* `AX = 0x0007`
* `EBX = 0`
* `ECX = 0`
* clear carry flag
* `EIP += 2`

The execution attempt records handled DOS interrupt count, the last interrupt vector, and the last DOS AH value.
The loader logs those values as well.

## Verification

* `cmd /c scripts\build_win32_x86.bat`: passed
  * MSVC C4819 warnings from external `spdlog` headers remain, but the build passed.
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe piu_1st`: passed
  * handled HLE trap count: `1`
  * last handled HLE trap opcode: `0xFB`
  * handled DOS interrupt count: `1`
  * last handled DOS interrupt vector: `0x21`
  * last handled DOS interrupt AH: `0x30`
  * execution passed the previous `INT 21h AH=0x30` stop at `0x020F38B5` and reached the next stop at `0x020F3954`
  * the next byte window includes `66 BA 78 00 66 B8 00 FF CD 21`, so the next DOS call appears to be `AX=0xFF00`, or `AH=0xFF`
* `build\vs2022_win32_debug\Debug\repiu_loader_win32.exe dos4gw_hello`: passed
  * Preserved `Hello, world!` on stdout
  * handled DOS interrupt count: `1`
  * last handled DOS interrupt AH: `0x30`

## Judgment

The first DOS service required by `piu_1st` was DOS version query, and the minimal HLE handling can pass it.
The next requirement is `INT 21h AH=0xFF`.
The existing hello-only path has temporary `AH=0xFF` handling that clears carry and sets `AL=0`, but it is not connected to the `piu_1st` path yet.

The next task is to document the meaning of `AH=0xFF` from the current trace/register state and connect the required minimal DOS HLE dispatcher handling.
