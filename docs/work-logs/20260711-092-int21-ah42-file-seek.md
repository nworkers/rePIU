# INT 21h AH=42h 파일 seek HLE 작업 로그

## 결과

DOS VFS open handle 기반 file seek helper를 추가했다. `AL=0` 시작 기준, `AL=1` 현재 위치 기준, `AL=2` 파일 끝 기준 seek를 지원하며, 성공 시 handle의 `file_offset`을 갱신하고 새 위치를 반환한다.

Win32 execution trampoline은 `INT 21h AH=42h`를 일반 DOS interrupt handler와 traced DOS interrupt handler 양쪽에서 처리한다. 성공 시 carry flag를 clear하고 새 위치를 `DX:AX`로 반환한다. 실패 시 carry flag를 set하고 `AX`에 DOS error code를 반환한다.

Win32 loader 로그에는 마지막 DOS seek handle, origin, signed offset, result position, 결과를 출력하도록 했다.

## 관찰

`piu_1st`는 `intro.ani` handle `0x0005`에 대해 `AH=42h` seek를 2번 수행했다. 마지막 관측 seek는 `AL=0`, offset `44544`, result position `44544`로 성공했다.

이 작업 후 기존 `AH=42h` 중단점은 통과했다. 다음 blocker는 relocated base + `0x000F7A0C`의 `CD 21`이며, 예외 시점 `EAX=0x00003E05`, `EBX=0x00000005`이다. 이는 handle `0x0005`에 대한 `INT 21h AH=3Eh` file close 요청으로 보인다.

## 검증

다음 명령으로 검증했다.

* `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`

결과는 통과했다. Win32 x86 빌드 중 third-party `spdlog` header의 기존 코드 페이지 경고 `C4819`가 계속 출력되지만 빌드 실패는 아니다.

# INT 21h AH=42h file seek HLE work log

## Result

Added an open-handle-based file seek helper to the DOS VFS. It supports `AL=0` start-relative, `AL=1` current-relative, and `AL=2` end-relative seek, updates the handle `file_offset` on success, and returns the new position.

The Win32 execution trampoline handles `INT 21h AH=42h` in both the normal DOS interrupt handler and the traced DOS interrupt handler. On success it clears carry and returns the new position in `DX:AX`. On failure it sets carry and returns a DOS error code in `AX`.

The Win32 loader log now prints the last DOS seek handle, origin, signed offset, result position, and result.

## Observation

`piu_1st` performed two `AH=42h` seeks on `intro.ani` handle `0x0005`. The last observed seek used `AL=0`, offset `44544`, and result position `44544`, and succeeded.

After this task, the previous `AH=42h` blocker is passed. The next blocker is `CD 21` at relocated base + `0x000F7A0C`, with exception-time `EAX=0x00003E05` and `EBX=0x00000005`. This appears to be `INT 21h AH=3Eh` file close for handle `0x0005`.

## Verification

Verified with:

* `powershell -ExecutionPolicy Bypass -File scripts\test_all.ps1 -SkipSetup`

The verification passed. The Win32 x86 build still reports the existing third-party `spdlog` code-page warning `C4819`, but it is not a build failure.
