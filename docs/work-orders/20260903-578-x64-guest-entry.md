# 작업 지시 20260903-578 — x64 guest entry: code cache로 들어가기

설계: [20260903-578](../design/20260903-578-x64-guest-entry.md)

## 변경 대상

| 파일 | 변경 |
|---|---|
| `src/platform/linux/guest_entry_x64.S` | 신규. guest 상태를 싣고 cache로 진입하는 브리지 |
| `include/repiu/platform/linux_x64_guest_entry.h` | 신규. 브리지의 state block과 선언 |
| `src/engine/execution/execution_trampoline.cpp` | `IsCodeCacheEntrySupported`, 엔진 resolver, `CallGuestCacheEntryTimed`, 진입 분기, 울타리 라우팅 |
| `CMakeLists.txt` | x64 게이트에 새 `.S` 추가 |
| `docs/analysis/linux-port-frontier.md` | 3.24절 |

## 구현 단계

1. `IsCodeCacheEntrySupported()`를 추가합니다. `__x86_64__`/`_M_X64`에서 true.
   기존 두 술어는 **바꾸지 않습니다.**
2. `guest_entry_x64.S`를 추가합니다. probe의 브리지와 같은 모양 — callee-saved
   저장, state block에서 guest GPR 적재(`ESP`는 `R15D`), 대상 호출, 상태 회수.
3. 엔진 resolver를 추가합니다. `frame->guest_source`를
   `FindAotCacheAddress(*context->aot_placement, ...)`로 조회하고, 없으면 0을
   반환해 thunk가 `INT3`을 놓게 합니다.
4. `CallGuestCacheEntryTimed(context)`를 추가합니다. dispatch를 설치하고,
   `R15D = guest_initial_esp`로 state를 채우고, `placement->entry_address`로
   브리지를 호출하고, 끝나면 dispatch를 해제합니다.
5. `GuestEntryThreadProc`에 x64 분기를 넣습니다. fault handler 설치는 direct
   경로와 같습니다.
6. `RunMinimalOriginalEntry`의 울타리를
   `IsDirectX86ExecutionSupported() || IsCodeCacheEntrySupported()`로 라우팅
   합니다.

## 검증 절차

1. **x64 `repiu` 실행** — 정지 지점이 움직여야 합니다. 어디까지 갔는지, boundary
   횟수, 종료 코드를 기록합니다.
2. **예산 안 종료** — timeout/stall이 회수해야 합니다.
3. Linux x64 Release `repiu_core_probe` — 전부 통과.
4. Linux i386 Release `repiu` 링크 + `repiu_core_probe` — 회귀 없음.
5. Win32 x86 Debug `repiu_aot_probe` — 회귀 없음.

## 완료 조건

- x64 실행의 정지 지점이 이동하고, 새 지점이 관측으로 기록됩니다.
- 회귀 없음.
- 작업 로그와 frontier 3.24절.

# Work order 20260903-578 — The x64 guest entry: into the code cache

Design: [20260903-578](../design/20260903-578-x64-guest-entry.md)

## Files to change

| File | Change |
|---|---|
| `src/platform/linux/guest_entry_x64.S` | New. The bridge that loads guest state and enters the cache |
| `include/repiu/platform/linux_x64_guest_entry.h` | New. The bridge's state block and declaration |
| `src/engine/execution/execution_trampoline.cpp` | `IsCodeCacheEntrySupported`, the engine resolver, `CallGuestCacheEntryTimed`, the entry branch, the fence routing |
| `CMakeLists.txt` | Add the new `.S` to the x64 gate |
| `docs/analysis/linux-port-frontier.md` | Section 3.24 |

## Implementation steps

1. Add `IsCodeCacheEntrySupported()`, true under `__x86_64__`/`_M_X64`. The two
   existing predicates are **not changed.**
2. Add `guest_entry_x64.S`, the same shape as the probe's bridge: save the
   callee-saved registers, load guest GPRs from a state block (`ESP` into
   `R15D`), call the target, write the state back.
3. Add the engine resolver: look `frame->guest_source` up with
   `FindAotCacheAddress(*context->aot_placement, ...)` and return zero when
   absent so the thunk plants an `INT3`.
4. Add `CallGuestCacheEntryTimed(context)`: install the dispatch, fill the state
   with `R15D = guest_initial_esp`, call the bridge at
   `placement->entry_address`, and clear the dispatch afterwards.
5. Add the x64 branch to `GuestEntryThreadProc`, installing the fault handler as
   the direct path does.
6. Route `RunMinimalOriginalEntry`'s fence on
   `IsDirectX86ExecutionSupported() || IsCodeCacheEntrySupported()`.

## Verification

1. **x64 `repiu` run** — the stopping point must move. Record how far it got, the
   boundary counts, and the exit code.
2. **Finishes within budget** — the timeout and stall machinery must reclaim it.
3. Linux x64 Release `repiu_core_probe` — all pass.
4. Linux i386 Release `repiu` link and `repiu_core_probe` — no regression.
5. Win32 x86 Debug `repiu_aot_probe` — no regression.

## Completion criteria

- The x64 stopping point moves and the new point is recorded as an observation.
- No regressions.
- A work log and frontier section 3.24.
