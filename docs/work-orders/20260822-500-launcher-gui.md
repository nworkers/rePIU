# 런처 GUI 작업 지시

설계: [20260822-500-launcher-gui.md](../design/20260822-500-launcher-gui.md)

1. Dear ImGui를 고정 태그로 `FetchContent` 선언하고, 코어 소스와 `imgui_impl_sdl3` ·
   `imgui_impl_opengl3`만 모은 정적 라이브러리 타깃을 추가합니다.
   `THIRD_PARTY_NOTICES.md`에 MIT 항목을 남깁니다.
2. `repiu::launcher::RomSetCatalog`를 추가합니다. 내장 프로필을 훑어 롬셋별 가용성과
   사유(`실행 가능`/`ZIP 없음`/`필수 엔트리 없음`/`CHD 없음`/`CHD 중복`)를 만들고,
   부모 롬셋과 표시 이름을 함께 담습니다. `std::filesystem`만 씁니다.
3. `repiu::launcher::LauncherSettings`를 추가합니다. `cfg/repiu.ini`를 `IniDocument`로
   읽고 쓰며, 창 크기·전체화면·swap interval·사운드 게인·마지막 선택 롬셋을 담습니다.
   해당 환경 변수가 설정돼 있으면 그 값이 이깁니다.
4. ImGui 런처 화면을 추가합니다. 목록·사유·부모 표시, 선택과 실행, 옵션 편집과 저장,
   취소(종료)를 제공합니다.
5. host `main.cpp`을 배선합니다. 인자가 없고 `REPIU_LAUNCHER`가 opt-out이 아니면 런처를
   돌리고, 결과 프로필로 기존 실행 경로에 들어갑니다. 인자가 있는 실행 경로는 바꾸지
   않습니다.
6. probe를 추가합니다: 합성 디렉터리로 만든 각 가용성 상태, 설정 왕복과 없는 파일과 잘못된
   값과 환경 변수 우선순위.
7. Win32 x86 Debug/Release로 `repiu`와 `repiu_aot_probe`를 빌드하고 probe를 실행합니다.
8. README와 `ARCHITECTURE.md`에 런처 진입 규칙과 `cfg/repiu.ini`를 반영합니다.

## 완료 조건

인자를 준 실행은 지금과 동일한 경로를 타야 합니다. 인자 없는 실행은 런처를 띄우고, 선택한
롬셋이 같은 프로세스에서 실행돼야 합니다. 가용성 판정과 설정 왕복은 probe로 검증되어야
하며, 화면 동작은 사용자 실행으로 확인합니다.

# Launcher GUI Work Order

Design: [20260822-500-launcher-gui.md](../design/20260822-500-launcher-gui.md)

1. Declare Dear ImGui through `FetchContent` at a pinned tag and add one static library target
   holding its core sources plus the `imgui_impl_sdl3` and `imgui_impl_opengl3` backends. Record
   the MIT entry in `THIRD_PARTY_NOTICES.md`.
2. Add `repiu::launcher::RomSetCatalog`: walk the built-in profiles and produce each ROM set's
   availability and reason (runnable, missing zip, missing required entries, missing CHD, multiple
   CHDs) with its parent and display name, using only `std::filesystem`.
3. Add `repiu::launcher::LauncherSettings`: read and write `cfg/repiu.ini` through `IniDocument`
   for window size, fullscreen, swap interval, sound gain, and the last selected ROM set, with a
   set environment variable overriding the stored value.
4. Add the ImGui launcher screen: the list with reasons and parents, selection and launch, option
   editing and saving, and cancel.
5. Wire `main.cpp`: with no arguments and no `REPIU_LAUNCHER` opt-out, run the launcher and
   continue into the existing execution path with its result. Leave the argument-bearing path
   untouched.
6. Add probes for each availability state over synthetic directories, and for settings round trip,
   a missing file, malformed values, and environment precedence.
7. Build `repiu` and `repiu_aot_probe` for Win32 x86 Debug and Release and run the probes.
8. Update README and `ARCHITECTURE.md` with the launcher entry rules and `cfg/repiu.ini`.

## Completion criteria

An argument-bearing invocation must take exactly the path it takes today, an argument-free one must
open the launcher and run the selected ROM set in the same process, availability and settings must
be probe-verified, and the screen itself is confirmed by a user run.
