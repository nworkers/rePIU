# 작업 지시서 20260906-610 — DPMI `INT 31h AX=0006` frontier

## 목표

Linux x64 기본 실행에서 `INT 31h AX=0006`의 실제 입력과 반환 계약을
계측하여 `Not enough memory to allocate file structures` 종료와의 인과를
확정합니다.

## 작업 순서

1. 기존 `HandleDpmiInterrupt31`의 `AX=0006` 경로와 selector table 조회를
   확인합니다.
2. `REPIU_DOS_INT_TRACE` 아래 opt-in DPMI entry/return register trace를
   추가합니다.
3. Linux x64 build와 core probe를 실행합니다.
4. `pumpit2a`를 기본 설정으로 실행하고 selector, descriptor base,
   `CX:DX`, CF, guest EIP를 비교합니다.
5. 계약 오류가 확인되면 관찰된 범위만 수정하고, 아니면 다음 frontier로
   분리합니다.
6. 분석 문서와 작업 로그를 갱신하고 커밋합니다.

## 완료 조건

* `AX=0006` entry/return의 입력 selector와 반환 `CX:DX`가 로그에 남습니다.
* 현재 descriptor base 기반 HLE 계약이 실제 호출과 일치하는지 판정됩니다.
* 기본 guest 출력과 기존 DOS termination 경계가 회귀하지 않습니다.
* core probe가 `24/24` 성공합니다.
* 다음 frontier가 추정이 아니라 로그 근거로 기록됩니다.

## 금지 사항

* 임의 selector/base를 주입하지 않습니다.
* 특정 guest EIP를 우회하지 않습니다.
* 관찰되지 않은 DPMI 함수의 성공 의미를 확장하지 않습니다.

## 진단 결과에 따른 구현 단계

* 원본 `0x010F1805`의 `66 8C DB`가 `MOV BX,DS`이고
  `0x010F1808`이 `INT 31h`임을 확인합니다.
* planner probe에서 이 명령이 `kGuardedSegmentRead`, DS, BX(GPR16)로
  분류되고 x64 HLE boundary로 fail-closed하는 것을 검증합니다.
* 실행 trace로 HLE가 `ThreadContext::guest_ds=0`을 읽어 `BX=0`을 만든
  것을 확인했으므로, guest entry가 속한 LE placement binding
  (이 실행에서는 selector `0x0024`)을 초기 logical DS로 시드합니다.
* LE stack object 4의 selector `0x0034`를 `guest_ss`에 넣는 수정은
  독립적인 stack-state 보정으로 유지하되, DPMI DS 입력의 근거와
  혼동하지 않습니다.
* `AX=0006`의 selector table 조회, invalid-selector 응답, descriptor
  base 반환은 변경하지 않습니다.

## English

### Objective

Capture the actual input and return contract of `INT 31h AX=0006` in the Linux
x64 default run and establish whether it causes the
`Not enough memory to allocate file structures` termination.

### Sequence

1. Review the existing `AX=0006` path in `HandleDpmiInterrupt31` and its
   selector-table lookup.
2. Add an opt-in DPMI entry/return register trace under
   `REPIU_DOS_INT_TRACE`.
3. Run the Linux x64 build and core probe.
4. Run `pumpit2a` with default settings and compare selector, descriptor base,
   `CX:DX`, CF, and guest EIP.
5. Change only an observed contract error; otherwise split the next frontier.
6. Update analysis and work-log documents and commit.

### Done criteria

* `AX=0006` entry/return selector and `CX:DX` are recorded.
* The current descriptor-base HLE contract is judged against the real call.
* Default guest output and the DOS termination boundary do not regress.
* The core probe passes `24/24`.
* The next frontier is recorded from log evidence rather than assumption.

### Prohibitions

* Do not inject an arbitrary selector or base.
* Do not bypass a specific guest EIP.
* Do not broaden unobserved DPMI success semantics.

### Diagnostic result and implementation stage

* The original bytes at `0x010F1805` (`66 8C DB`) are `MOV BX,DS`, followed
  by `INT 31h` at `0x010F1808`.
* The planner classifies this instruction as a guarded DS read into BX(GPR16),
  and x64 fails closed to the existing HLE boundary.
* The runtime trace proves that the boundary read logical DS as zero. Seed
  `ThreadContext::guest_ds` from the LE placement binding containing the guest
  entry (selector `0x0024` in this run) so `AX=0006` receives the real logical
  DS selector.
* Keep the independent logical SS seed from LE stack object 4 (`0x0034`) for
  guest-stack semantics; it is not the selector consumed by this DPMI call.
* Keep the `AX=0006` selector-table lookup, invalid-selector response, and
  descriptor-base return unchanged.

### 추가 진단 단계

`AX=0006` 성공 뒤에도 남는 오류 문구의 caller를 분리하기 위해
`REPIU_DOS_INT_TRACE=1`일 때 `AH=40h` write의 guest EIP, buffer 주소,
handle, byte count를 기록한다. 원본 오류 printer가 `EAX=메시지 주소`,
`EDX=종료 코드`를 받는다는 정적 분석 결과와 write trace를 대조한다.

### Additional diagnostic stage

To separate the caller of the remaining error message after successful
`AX=0006`, record the guest EIP, buffer address, handle, and byte count for
`AH=40h` writes when `REPIU_DOS_INT_TRACE=1`. Correlate that trace with the
static calling convention of the original error printer:
`EAX=message address`, `EDX=exit code`.

### 최종 범위 판정

검증 결과 `AX=0006`, `CON` open/write, DOS 종료는 모두 정상이다. 원본
allocator는 요청 8을 `0x1000`으로 정규화한 뒤
`memory_base=0x0158CC90`에서 `requested_end=0x0158DC90`을 거부한다.
따라서 이 작업의 다음 구현은 DPMI 또는 표준 출력 수정이 아니라
DOS/4GW memory-boundary/headroom 설계로 분리한다.

`pumpit1` 비교 실행은 같은 오류 문구와 정상 종료를 확인하는 데 사용했지만,
allocator 진단 오프셋은 `pumpit2a`에만 유효하다. `pumpit2`는 CHD mount
directory 부재로 비교하지 못했다.

### Final scope decision

Verification shows that `AX=0006`, `CON` open/write, and DOS termination all
work correctly. The original allocator normalizes request 8 to `0x1000`, then
rejects `requested_end=0x0158DC90` because `memory_base=0x0158CC90`.
The next implementation is therefore split into DOS/4GW memory-boundary and
headroom design, not DPMI or standard-output changes.

The `pumpit1` comparison confirmed the same error text and normal termination,
but the allocator diagnostic offsets are valid only for `pumpit2a`. `pumpit2`
could not be compared because its CHD mount directory is absent.
