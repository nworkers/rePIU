# 20260715-206-exception-diagnostic-and-buffer-provenance

## 1. 개요 (Overview)

### 목적 (Objective)
- SEH 예외 발생 시 진단 바이트 윈도우가 실제 예외 주소를 가리키도록 AOT 게스트 주소 매핑을 활용해 수정한다.
- 65,536-레코드 디코드 루프 내 `mov [ebx+ebp], al` 명령(opcode 88)에서 발생하는 미매핑 쓰기 `0x045D3EB0` 오류를 shadow memory HLE 처리가 가능하도록 확장하여 해결한다.
- Correct the exception diagnostic byte window to point to the actual mapped guest EIP instead of a stale one.
- Handle the unmapped memory store at `0x045D3EB0` generated by `mov [ebx+ebp], al` (opcode 88) via shadow memory HLE extension.

### 기능 검증 (Functional Verification)
- `repiu_supervisor_win32.exe` 및 `aot-dynamic` 백엔드를 통해 실행한다.
- `Relocated exception byte window`가 `invalid` 또는 stale POP ES 대신, 실제 예외 유발 명령인 `mov [ebx+ebp], al` (cache/guest bytes: `88 04 2B ...`)이 들어있는 올바른 영역을 포커싱(예: `[88] 04 2B ...`)하여 출력하는지 확인한다.
- 65,536-레코드 디코드 루프의 `mov [ebx+ebp], al` 예외가 shadow memory HLE를 통해 정상적으로 처리되어, 게스트 스레드가 `0x030873F4`에서 튕기지 않고 다음 단계로 계속 진행하는지 확인한다.
- `0x030F3A21` (`mov al, gs:[ebx]`) 에서 가용 LDT limit 초과로 인한 크래시가 유발되지 않고, 게스트 스레드가 이 지점을 완전히 넘어 후속 기동 단계로 전진하는지 관측한다.
- Run the executable under the supervisor, verify that the diagnostic window displays the correct instruction (`88 04 2B`), and verify that the guest proceeds past the loop and beyond `0x030F3A21` into downstream execution.
